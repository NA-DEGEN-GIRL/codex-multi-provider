# 실험용 Windows Codex 앱 사용법

**실험용 앱을 열면 Astra가 DeepSeek 또는 GPT 자식에게 작업을 맡길 수 있습니다.** 평소 쓰는 Codex는 시작 메뉴나 **원래 Codex 앱 열기** 버튼으로 계속 사용할 수 있습니다.

기준일: 2026년 9월 12일. 현재 DeepSeek는 **V4.1 Flash (`deepseek-flash`), 추론 수준 `max` 고정**입니다.

## 1. 실험용 앱 열기

1. 탐색기에서 `C:\dev\codex-multi-provider` 폴더를 엽니다.
2. `Open-Experimental-Codex.cmd`를 더블클릭합니다. 실험실 창이 열려 있다면 아래쪽 **실험용 Codex 앱 열기**를 눌러도 됩니다.
3. 로그인 화면이 나오면 실험용 앱에서 ChatGPT에 로그인합니다. 이 앱은 평소 쓰는 앱과 로그인·대화·설정을 따로 저장합니다.
4. 처음에는 테스트용 빈 폴더를 프로젝트로 엽니다. 부모 모델은 **Astra**를 선택합니다.

실험용 앱은 **내가 선택한 프로젝트 폴더에 파일을 만듭니다.** 실험실 버튼처럼 매번 새 테스트 폴더를 자동으로 만드는 방식은 아닙니다.

DeepSeek 키는 이미 저장한 것을 사용합니다. 별도의 Claude Code 앱을 열 필요는 없습니다.

## 2. 첫 작업 요청하기

아래 요청을 새 작업에 붙여 넣으면 DeepSeek와 GPT가 함께 일하는지 확인하기 좋습니다.

> 작은 Python 모듈과 테스트를 만들어줘. 구현은 DeepSeek 역할의 자식에게, 검토는 GPT 자식에게 위임하고, 둘의 완료를 기다린 다음 테스트해줘. 마지막에는 담당별 실제 모델, 만든 파일, 테스트 통과 여부를 표로 알려줘.

확인할 흐름은 다음과 같습니다.

**Astra가 일 배분 → DeepSeek가 구현 → GPT가 검토 → Astra가 완료를 기다린 뒤 테스트 → 결과 보고**

같은 유형의 요청을 실제 Windows 앱에서 실행해 DeepSeek가 Python 파일 2개를 만들고, GPT가 검토하고, Astra가 테스트 9개를 통과시킨 기록이 있습니다. [실행 사례 보기](test-results-20260912-1706.md).

### Astra가 모델을 스스로 고르게 하고 싶을 때

> 간단한 Python 기능과 테스트를 만들어줘. 구현과 검토를 자식에게 나눠 맡기고, 작업의 난이도와 비용을 고려해 DeepSeek 또는 GPT를 직접 선택해줘. 자식들의 완료를 기다린 뒤 테스트하고, 실제 선택한 모델과 선택 이유를 알려줘.

자율 선택에서는 DeepSeek를 쓰지 않을 수도 있습니다. ‘GPT 자식’이라고만 지정하면 GPT 중 어떤 모델을 쓸지도 달라질 수 있습니다. 실제 사용자 테스트에서는 검토 자식도 Astra였습니다.

## 3. 진행 상황과 결과 확인하기

앱의 작업 메시지와 마지막 보고를 먼저 확인하고, 결과 파일은 **이번에 선택한 프로젝트 폴더**에서 엽니다. 실험실의 **최근 생성 파일 폴더** 버튼은 실험실 결과용입니다.

모델 사용 여부를 확실히 확인하고 싶으면 이 Codex 대화에서 다음처럼 요청하세요. 대괄호 부분만 바꿔 쓰면 됩니다.

> 실험용 Windows Codex 앱에서 방금 실행한 작업을 확인해줘. 작업 폴더는 [프로젝트 폴더 경로]이고, 요청은 [했던 요청 요약]이야. 세션 기록에서 실제 부모·자식 모델과 Flash의 max 여부를 확인하고, 누가 무엇을 했는지와 테스트 결과를 표로 정리해줘. 기존 기록만 읽고 새 실행은 하지 마.

‘세션 기록’은 모델과 도구가 실제로 수행한 일을 저장한 파일입니다. 직접 JSON을 읽을 필요는 없습니다. 분석할 때 사용할 위치는 `C:\dev\codex-multi-provider\profiles\desktop-runtime\sessions`입니다.

## 4. 원래 Codex로 돌아가기

**시작 메뉴의 Codex**를 열거나 실험실 아래쪽 **원래 Codex 앱 열기**를 누릅니다.

| 구분 | 원래 앱 | 실험용 앱 |
|---|---|---|
| 여는 방법 | 평소 바로가기 / **원래 Codex 앱 열기** | `Open-Experimental-Codex.cmd` / **실험용 Codex 앱 열기** |
| 작업 엔진 | 설치된 원본 | DeepSeek 자식 지원을 추가한 버전 |
| 대화·설정·로그인 | 기존 환경 | 실험용으로 별도 저장 |
| 프로젝트 파일 | 선택한 폴더 | 선택한 폴더 |

두 창은 겉모습이 비슷할 수 있습니다. 버튼으로 연 창과 그 창의 프로젝트를 기준으로 구분하세요. 같은 프로젝트 폴더를 두 앱에서 열면 프로젝트 파일 자체는 공유됩니다.

**현재 방식은 앱 창을 골라 사용하는 전환입니다.** 이미 실행 중인 대화의 엔진을 즉시 바꾸거나 두 앱 사이로 대화를 옮기는 기능은 구현하지 않았습니다.

## 5. Flash max와 연결 설정 바꾸기

Flash의 추론 수준은 이 실험 환경에서 **항상 `max`로 적용**됩니다. GPT의 설정은 따로 유지됩니다. 프로필을 다시 만들거나 실험용 앱을 다시 실행해도 Flash max 정책이 적용됩니다.

max 고정 적용 전부터 실험용 앱을 켜 두었다면, 작업이 끝난 뒤 **실험용 앱만 종료하고 다시 열어 새 작업을 시작**하세요. 과거 테스트의 `low` 기록은 당시 실행값이므로 그대로 남습니다.

DeepSeek 연결 정보는 실험실의 **DeepSeek API 설정**에서 변경합니다.

| 항목 | 현재 값 |
|---|---|
| API 주소 | `https://api.deepseek.com` |
| 모델 ID | `deepseek-flash` |
| API 키 | 등록됨 — 채팅에 붙여 넣지 않고 설정 창에서 입력 |
| Flash 추론 수준 | `max` 고정 |

실험실의 다음 테스트에는 저장한 연결 설정을 사용합니다. **이미 만들어진 실험용 앱 설정에 주소·모델 변경을 반영하려면 별도 갱신이 필요합니다.** 앱을 닫은 뒤 Codex에 ‘저장한 DeepSeek 연결 설정을 실험용 앱에도 반영해줘’라고 요청하면 됩니다. 직접 실행할 명령은 [개발자용 참고 문서](technical-reference.md)에 있습니다.

## 6. 막혔을 때

| 증상 | 먼저 해볼 일 |
|---|---|
| `pwsh.exe`를 찾을 수 없다고 나옴 | 오류 창을 닫고 위 프로젝트 폴더의 현재 `Open-Lab.cmd` 또는 `Open-Experimental-Codex.cmd`를 다시 실행합니다. 이 오류를 해결한 실행기로 교체되어 있습니다. 계속되면 오류 문구를 알려주세요. |
| 눌렀는데 어떤 앱이 열린 것인지 모르겠음 | 실험실에서 **실험용 Codex 앱 열기**를 누른 뒤 기록창을 봅니다. `패치 앱 서버 실행 확인`은 확장 엔진 시작을 확인했다는 뜻입니다. |
| ‘실행 요청’만 보이고 확인 문구가 없음 | 기존 실험 창으로 연결됐거나 앱 시작 확인이 아직 안 된 상태일 수 있습니다. 열린 창을 확인하고 실행기 기록 분석을 요청하세요. 이 문구만으로 실행 실패·성공을 단정하지 않습니다. |
| 예전 대화가 안 보임 | 실험용 앱은 별도 대화 목록을 씁니다. **원래 Codex 앱 열기**로 기존 환경을 여세요. |
| Flash를 지정했는데 사용 여부가 불분명함 | 새 작업의 실제 세션 기록 분석을 요청하세요. 위 3번의 요청문을 사용할 수 있습니다. |
| 실험실에서 GPT 로그인 만료 오류가 남 | 원래 Codex 앱에서 정상 요청을 한 번 보낸 뒤 실험실 테스트를 다시 실행합니다. |
| 실험실에서 출력이 잠시 멈춤 | 경과 시간과 마지막 출력 시간을 확인합니다. 자유 작업은 모델 응답 대기에 최대 10분 제한이 있습니다. 종료 시 오류가 남으면 기록을 확인하세요. |

Windows 앱에서의 혼합 작업 실행과 실제 모델 사용은 기록으로 확인했습니다. **앱을 완전히 종료한 뒤 기존 DeepSeek 작업을 재개하는 동작은 아직 검증하지 않았습니다.** 앱 업데이트 후에는 실행 연결이 계속 맞는지 다시 확인할 필요가 있습니다.
