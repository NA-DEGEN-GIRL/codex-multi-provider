# 수정 98 — Claude Code 로그인 프로필과 공통 작업

컨텍스트·압축 기본값, UltraCode 및 사용량 표시는 [수정 99](claude-defaults-usage-99.md)에서 변경되었다.
아래 초기 구현의 고정 컨텍스트·압축 값은 현재 기본값이 아니다.

## 목적과 실행 경계

Codex 작업 공간의 공통 작업을 Claude 계정으로 이어서 실행한다. Claude 프로필은 외부 API 키
프로필과 별개다. 설치된 공식 Claude Code CLI가 OAuth 로그인, Claude 도구 실행 및 자체 세션을
처리한다. 관리 앱은 Claude OAuth 토큰을 읽거나 API용 Bearer 토큰으로 변환하지 않는다.
참고한 [opencode-claude-auth-v2](https://github.com/heymaaz/opencode-claude-auth-v2)의 토큰 재사용
방식은 구현하지 않았다.

현재 구현 대상은 **Windows 로컬 작업**이다. SSH에 Windows 실행 경로나 인증을 게시하지 않는다.
SSH의 Claude 실행은 해당 서버의 CLI, 프로필별 로그인, 실행기 배포를 별도로 구현해야 한다.
이를 지원하는 것처럼 GPT로 대신 실행하거나 인증을 자동 복사하지 않는다.

공식 문서: [인증](https://code.claude.com/docs/en/authentication),
[프로그래밍 방식 실행](https://code.claude.com/docs/en/headless),
[CLI 인자](https://code.claude.com/docs/en/cli-reference).

## 구성

- WPF `ClaudeProfileSettings`, `ClaudeProfilePresentation`: 프로필 생성, 로그인, 상태 확인,
  모델·추론 강도·컨텍스트·자동 압축 설정. Claude 카드에는 GPT 주간 한도나 리딤 횟수를 표시하지 않는다.
- `control_center.py`: `profile.add(kind=claude_code)`, `claude.login`, `claude.status`,
  `claude.settings`. 설정 변경은 해당 프로필이 작업을 마친 뒤 재시작하도록 예약한다.
- `claude_profiles.py`: 설정 검증과 Codex 모델 카탈로그·agent binding 생성. Claude 전용 런타임
  기능 표시가 없는 바이너리로는 실행하지 않는다.
- `claude_auth.py`: 설치된 CLI 확인, 프로필별 로그인 실행, 인증 상태의 허용된 필드만 반환.
- `claude_runner.py`, `claude_protocol.py`, `claude_permission_mcp.py`: 유계 JSONL 통신,
  CLI 스트림 변환, 재개 장부, 승인 중계, 취소 시 해당 자식 프로세스 트리 정리.
- `claude_skills.py`: 켜진 공통 개인 스킬과 프로젝트 `.agents/skills`를 Claude plugin으로 노출.
- Rust `core/src/tasks/claude_code*`: Codex의 턴 실행·승인·이벤트·공통 기록과 실행기를 연결.

## 사용 순서

1. 공식 네이티브 Claude Code CLI 2.1.282 이상을 Windows에 설치한다. 실제 CLI는 사용자가
   설치·업데이트한다. 이 최소 버전은 구현에 사용한 실행 인자를 로컬 `--help`로 확인한 버전이다.
2. 프로필 `＋`에서 Claude를 선택하고 이름과 모델 설정을 저장한다.
3. 열린 Claude 로그인 창에서 계정 인증을 마친 뒤 관리 앱에서 로그인 상태를 확인한다.
4. Claude 프로필에서 로컬 프로젝트의 공통 작업을 연다. 다른 Codex/Claude 프로필로 같은
   작업을 열면 공통 기록을 이어받는다. CLI 고유 세션 파일을 Codex 기록 파일로 복사하지 않는다.
5. 모델 기본값은 Claude 설정에서 바꾼다. Codex 하위 에이전트 정책 메뉴는 Claude에 적용하지
   않는다. Claude의 도구·하위 작업은 Claude CLI가 처리한다.

추론 강도는 CLI에 매번 `--effort`로 요청하므로 `max`도 재실행 후 유지된다. 현재 Opus·Sonnet·Fable
별칭의 지원 값은 low/medium/high/xhigh/max다. 조직 정책이나 별칭이 가리키는 모델에 따라 실제 강도가
제한될 수 있으며, UI 값은 요청한 기본값이다. [공식 강도 설정](https://code.claude.com/docs/en/model-config#adjust-effort-level)을 참조한다.

Claude CLI는 Codex OS 샌드박스의 자식 도구가 아니다. 제한된 Codex 실행 환경에서는 실행기 전체의
권한 차이를 명시하고 턴 단위 승인을 받아야 한다. 승인 불가 정책에서는 거절한다. 전체 접근에서는
실행할 수 있으며, Claude 자체 도구 승인 요구는 계속 중계한다. 지원하지 않는 승인 형식은 허용하지 않는다.

Codex의 별도 검토 모드·수동 압축 명령·JSON schema 구조화 출력은 이 실행기에서 지원하지 않는다.
검토는 일반 메시지로 요청하고, 압축은 Claude 자동 압축을 사용한다. 이 경로들은 설명과 함께 거절하며
Claude 프로필에서 OpenAI 모델 호출로 넘어가지 않는다. Claude Plan 모드는 전달하지만 도구가 임의로
Plan 제한을 해제하도록 승인하지 않는다.

## 계정 전환과 캐시

공통 기록은 작업별 하나이고, Claude CLI 세션은 계정·작업·작업 경로·모델·추론·압축 설정별로 분리한다.
스킬 내용, 프로젝트 지침, CLI 버전도 세션 재사용 조건에 포함된다.
프로젝트 AGENTS·사용자 지침·추가 개발 지침은 안정된 시스템 지침으로 전달하고 그 해시도 재사용 조건에
포함한다. 지침은 80,000 UTF-8 바이트 한도로 검증하며, Windows 명령행 길이 제한을 피하도록
보호된 임시 파일을 공식 CLI의 `--append-system-prompt-file`로 전달한다. 파일은 실행 후 정리한다.

- Claude A → B → A: A가 이미 본 완료 턴은 다시 전송하지 않는다. B에서 추가한 완료 턴만 A에
  전달한다. 두 계정이 같은 비공개 추론 서명이나 CLI 세션을 사용하지 않는다.
- GPT → Claude: 사용자/도우미/도구 결과를 평문 이력으로 전달하고, 과거 요청의 재실행과 현재
  요청을 구분한다. 공급자의 비공개 reasoning 객체는 전달하지 않는다.
- Claude → GPT: 공통 저장소의 일반 메시지·도구 기록·검증된 평문 요약을 사용한다.
- 같은 프로필에 다른 Claude 계정으로 로그인한 경우에도 인증 주체 확인값이 달라지면 기존
  CLI 세션을 재사용하지 않는다. 인증 주체를 확인할 수 없으면 새 세션으로 시작한다.
- 과거 메시지 수정·롤백·포크, 실행 중단, 완료 기록 저장 실패는 재개 장부를 무효화한다.

CLI 완료 응답만으로 장부를 확정하지 않는다. Rust가 공통 기록을 저장하고 flush한 뒤 완료된
턴별 fingerprint를 실행기에 보내야 장부의 dirty 표시를 해제한다. 그 사이 다른 계정이 추가한
턴은 아직 Claude가 보지 않았으므로 covered 집합에 넣지 않는다.

이 방식은 요청 앞부분을 안정시키고 중복 전송을 줄인다. 공급자 서버의 실제 캐시 적중이나 유지
시간을 보장하지 않으며, 계정 간 캐시 공유를 뜻하지 않는다. 실제 캐시 토큰은 CLI가 반환한
사용량만 사용한다. 확인되지 않은 요금·한도·캐시 예상치를 GPT 규칙으로 계산하지 않는다.

## 컨텍스트와 압축

기본값은 컨텍스트 200,000 토큰, 자동 압축 85%다. 설정 범위는 컨텍스트 100,000~1,000,000,
압축 비율 50~95%이며, CLI의 최소 압축 임계치 때문에 두 값을 곱한 임계치는 100,000 이상이어야 한다.
설정 수치가 공급자 모델의 실제 지원 한도를 늘려 주는 것은 아니다.

Claude CLI에 계산한 압축 임계치를 전달한다. 새 세션으로 넘기는 공통 이력에도 입력 예산을 적용한다.
예산에 맞는 검증된 요약이 없으면 오래된 요청을 조용히 버리지 않고 설명 가능한 오류로 멈춘다.

압축 이벤트만 도착한 경우 요약을 만들어 낸 것으로 간주하지 않는다. CLI가 보낸 요약 또는 해당
실행의 정확한 UUID transcript에서 확인한 `isCompactSummary`를 보조 요약으로 공유한다. 후자는
`CLAUDE_CONFIG_DIR/projects/*/<session-id>.jsonl`의 제한된 끝부분만 읽는다. 인증 파일은 읽지 않는다.
보조 요약과 최종 공통 요약은 20,000 UTF-8 바이트를 넘으면 잘라 쓰지 않고 폐기한다.
내부 요약의 `isCompactSummary`만으로 공통 이력의 포함 범위를 추정하지 않는다. 압축이 발생한
성공 턴 뒤에는 같은 Claude 세션에서 도구 없이 전체 문맥의 공통 요약을 한 번 생성한다.
이는 **Claude 모델 응답 한 번의 추가 사용량**이 발생할 수 있다. 모델 자체가 요약한 결과의 의미를
완벽히 보존한다고 보장하는 기능은 아니며, 원본 이력을 삭제하지 않는다.

이 별도 요약이 성공했을 때만 당시 전달한 완료 턴의 fingerprint를 기록한다. 현재 턴과 다른
계정이 동시에 추가한 턴은 그 범위에서 제외한다. 새로운 입력이 예산을 넘을 때 검증된 요약으로
해당 턴만 대체하여 전달하고, 내용이 수정되었거나 요약이 실패·취소된 경우 원본을 사용한다.
요약 요청 중 다시 압축되더라도 추가 요약을 반복하지 않는다. 요약을 확인하지 못한 상태에서
Claude 실행기 입력 예산까지 초과하면 과거 내용을 임의로 잘라 내지 않는다.
GPT 쪽 기존 재구성은 모델 기본 지침·도구·프로젝트 지침 공간도 차감한다. 이 필수 공간조차 담지 못하는
비현실적으로 작은 모델 설정에서는 이전 대화를 담지 못했다는 안내가 나올 수 있으며, 설정한 전체
컨텍스트가 모두 대화 이력에 쓰인다고 계산하지 않는다.

## 저장 위치와 스킬

| 자료 | 위치 | 관리 주체 |
|---|---|---|
| 로그인·Claude 원본 세션 | `%LOCALAPPDATA%/codex-multi-provider/claude-profiles/<profile-id>` | Claude CLI |
| 프로필 설정·마스킹된 상태 | `<repo>/work/control-center/state.json` | 관리 앱 |
| 재개 장부 | `<repo>/work/control-center/claude/sessions/<profile-id>/<task-hash>` | 실행기 |
| 생성 스킬 plugin | `<repo>/work/control-center/claude-skill-plugins/<profile-id>/<content-hash>` | 관리 앱 |
| 이미지 전달 파일 | `<profile-codex-home>/claude-image-handoff/<content-hash>.png` 또는 `.jpg` | 패치한 Codex 런타임 |
| 공통 작업 기록 | 기존 canonical Codex 저장소 | 패치한 Codex 런타임 |

스킬 plugin은 원래 `SKILL.md`를 읽도록 안내하는 작은 진입점이다. 파일·참고자료의 상대 경로는
원본 스킬 디렉터리를 기준으로 해석한다. 원본 스킬이나 모델 가중치를 복제하지 않는다. 이 기능이
Codex 전용 MCP 도구·브라우저·플러그인 연결을 Claude 도구로 자동 변환하지는 않는다.

공통 기록에 저장된 PNG/JPEG 스크린샷은 바이트를 바꾸지 않고 로컬 이미지 파일로 전달한다.
Claude가 필요할 때 자체 Read 도구로 열며, 파일을 전달한 사실만으로 이미지를 읽었다고 표시하지 않는다.
사용자 첨부와 도구의 이미지 결과를 함께 지원하고 공통 원본 기록은 수정하지 않는다. 이미지당 8 MiB,
턴당 중복을 제외한 총 64 MiB 한도와 이미지 디코딩 메모리 64 MiB 한도가 있다.
원격 이미지 URL·오디오·지원하지 않는 형식은 명시적으로
거절하며, 대화 전환을 위해 몰래 내용을 버리지 않는다. 요약의 포함 범위 검증은 이미지 변환 전에 수행한다.

환경변수의 다른 계정 API 인증은 데스크톱 및 Claude 실행 단계에서 제거한다. OAuth 비밀값과
전체 인증 출력은 관리 상태·로그·Git에 저장하지 않는다. 공개 저장소에는 위 경로의 실제 내용을 넣지 않는다.

Claude 프로필에는 다른 프로필의 SSH 연결·자동 연결 설정을 상속하지 않는다. 명시적인 원격 준비도
네트워크 작업 전에 거절한다. 공통 원격 프로젝트 기록은 보존하지만 이 프로필에서 원격 실행은 지원하지
않는다. 로컬 설정 적용·재시작의 작업 종료 확인은 그대로 유지한다.

## 검증 상태

2026-09-28 확인:

- Python 전체 회귀 1,775개 실행, 실패·오류 0개, 환경 조건에 따른 58개 제외. 실제 GUI를 띄우는
  `test_launchers.py`는 실행 대상에서 제외했다. 테스트 검색 경로에 `scripts`와 `tests`를 넣고,
  SSH pump fixture에는 새 후보 배포의 실제 `ssh/ssh.exe`를 지정했다.
- 위 검사에는 Claude 설정·공유 스킬 11개, 실행기 28개(이후 경계값 검사를 추가한 실행기 32개도 별도로 통과), 로컬 전용 SSH 경계 6개가 포함된다.
  이 전체 검사에서는 네이티브 실행 파일이 필요한 Claude 통합 검사를 제외했으며 아래에서 별도로 실행했다.
- 관리 서비스 Rust 시험 62개 통과. 수정 98 관리 앱 후보 빌드와 전용 UI 검사 4개 통과.
  173개 동결 Python 파일이 소스와 일치하고 배포 manifest의 197개 파일 해시를 독립 검토했다.
- 전체 WPF 레이아웃 시험은 기존 HEAD에서도 같은 `LayoutSelfTest.cs:345` 선택 항목
  NullReferenceException으로 실패한다. Claude 전용 UI 검증과 구분한다.
- 최종 실행 파일의 공유 편집 15개·공통 저장소 16개 검사가 통과했다.
- Claude→다른 Claude→GPT 압축 전달에서 검증된 요약과 이후 턴을 유지하고, 이미 요약한 원본을
  요청에서만 제외하며 공통 원본을 보존하는 것을 확인했다. GPT 수신 시험은 40,000/34,000 토큰을
  사용해 기본 지침 공간을 남기면서 원본 이력은 예산을 넘게 했다. 추가 공급자 압축 호출도 없었다.
- 최종 `codex-app-server.exe`에서 Claude 통합 검사 8개(7개 기능 시나리오와 fixture 검사)가
  최종 스키마를 포함한 빌드에서 181.0초에 통과했다. OAuth 미로그인 거절, 모델 목록, UTF-8 스트리밍, 기록 저장 후 장부 확정,
  원래 세션 재개, AGENTS 전달, GPT 왕복, A→B→A 델타, 실제 승인 helper 중계,
  취소 시 부분 기록 보존·장부 무효화, Plan, 압축 요약 왕복을 검증했다. 도구 진행 알림이
  Codex 동적 도구 실행 요청으로 잘못 해석되지 않는 것도 확인했다.
- 실제 Claude 계정 로그인과 모델 호출은 수행하지 않았다. 시험용 Claude CLI와 loopback GPT
  응답 서버를 사용했으며 실제 계정 캐시 적중·요금·OAuth 브라우저 완료 검증은 별도다.
- 앱 안에서 검사를 실행하면 공통 기록 경로 환경변수가 상속될 수 있으므로, 실행 시험은 해당
  변수를 제거하고 홈·SQLite·공통 기록을 임시 경로에 지정한다. Rust 통합 검사 준비 중 발견한
  상속 누락은 테스트 실행 전에 정상 취소하고 테스트 helper 자체에서 차단했다.
- Rust 집중 검사 64개를 확인했다. 첫 실행의 63개 통과와 테스트 실행기 종료 계약을 고친 뒤의
  나머지 1개 통과를 합친 결과다. 시간 제한은 늘리지 않았고 배포 코드는 바뀌지 않았다.
  기존 `portable_context` 35개, Claude의 이미지·이벤트·요약·기록 재구성 및 스키마 검사를 포함한다.
  Windows에서 테스트 실행기가 EOF를 기다리던 부분을 실제 실행기처럼 `committed` 뒤 종료하도록
  고쳤다. Rust·Just·Python 포맷 검사는 통과했다. 전체 `just fmt`는 DotSlash 누락으로 실패했지만,
  고정된 Buildifier 8.5.1의 해시를 검증하고 같은 Bazel/Starlark 188개 대상을 별도로 검사해 통과했다.
- 설정 스키마를 다시 생성했다. 누적 패치를 새 worktree에 적용해 manifest의 트리 ID와
  일치함을 확인했으며 원래 런타임 인덱스는 변경하지 않았다.
- 엄격한 Clippy 검사는 수정 97에도 존재한 관리 저장소 초기화의 잠금 유지와 종료 토큰 초기화의
  `expect` 두 지점에서 실패했다. 이전 누적 패치와 해당 함수·블록이 같은지 확인했다. 이번 기능과
  무관한 실행 코드를 바꾸지 않고 보존하며, 이 두 규칙을 경고로 낮춘 별도 검사 결과와 구분한다.
  같은 7개 패키지의 최종 `just fix`는 종료 코드 0으로 완료됐다. 이 명령의 성공을 엄격한 Clippy
  전체 통과로 해석하지 않는다. 위 두 실행 코드 진단과 `shared_history_refresh.rs`의 테스트
  `needless_collect` 진단이 남았으며 이 테스트 블록도 수정 97과 같음을 확인했다. 기존 enum 크기
  경고도 남아 있다. Rust 파일 3,697개를 대조해 마지막 자동 정리는 테스트 파일 3개에 한정됨을
  확인했으며, 실행 코드는 바뀌지 않았다.
- 공개 텍스트 612개와 누적 패치에서 토큰·개인 경로 패턴의 검출은 없었다. 기존 개인용 이전 문서 등
  별도 미추적 파일 3개는 제외했다. 이 패턴 검사는 모든 개인정보의 부재를 증명하는 검사는 아니다.

`scripts/build-manager.ps1 -StageOnly`는 배포 후보를 만들고 후보 폴더의 `candidate.json`에 실행
경로를 기록한다. 활성 `current.json`과 실행 중 작업은 바꾸지 않는다. 일반 실행 적용 전에는
관리 앱과 native runtime 양쪽의 검증 결과를 확인해야 한다.

## 적용 시 주의

2026-09-28 다음 실행 대상으로 관리 앱 `20260928-115405-935`(수정 98)와 네이티브 런타임
`20260928-123915-e04fc1`을 등록했다. 최종 누적 패치 복원 트리는
`edbbae73532603534316520fbc5702d528d5dd48`이며, 실행 중인 프로필·서비스는 재시작하지 않았다.

새 UI와 실행 중인 이전 관리 서비스는 IPC 번호가 같아도 Claude RPC 지원이 다를 수 있다.
이전 서비스가 살아 있으면 Claude 생성·설정은 오류로 거절된다. 새 메타데이터는 이전 런타임에서도
읽히지만, 계정 전환·압축 요약의 새 의미까지 이전 실행기가 처리하는 것은 아니다.
따라서 작업을 마친 뒤 관리 앱의 **완전 종료**를 사용하고 다시 열어 관리 서비스와 전환에 참여하는
모든 로컬 프로필을 새 실행기로 시작한다. 창만 닫았다 여는 것으로 적용 완료라고 판단하지 않는다.

검증 뒤 배포 포인터를 새 후보로 바꾸는 것만으로 현재 프로세스가 종료되지는 않는다. 다만 이후 관리창을
열면 시작 시 자동 업데이트 검사가 오래된 프로필에 작업 종료 후 재시작을 예약할 수 있다.
즉 포인터 변경을 "앞으로도 명시적 종료 전까지 어떤 자동 재시작도 없다"고 설명해서는 안 된다.

## 실계정 적용 후 확인

아래 확인은 실제 로그인과 모델 사용량이 필요하며 이번 구현 검사에서는 수행하지 않았다.

1. 작업 종료 후 완전 종료·재실행하고 수정 98을 확인한다. Claude 프로필을 만든 뒤 공식 로그인
   창에서 인증하고, 관리 앱의 로그인 상태가 해당 계정으로 확인되는지 본다. 토큰 파일을 열지 않는다.
2. 민감하지 않은 짧은 시험 작업에서 Claude A → GPT → Claude A로 전환한다. 앞에서 정한 작은
   사실을 이어서 답할 수 있는지, 공통 목록에는 같은 작업 하나가 남는지 확인한다.
3. 두 Claude 계정을 쓴다면 같은 시험 작업에서 A → B → A로 전환한다. 각 프로필의 로그인
   상태가 올바른지 확인하고, CLI가 보고한 캐시 사용량이 있을 때만 실제 적중으로 판단한다.
4. 프로젝트 또는 켜진 공통 스킬 하나를 요청해 원본 문서를 읽는지 확인한다. Codex 전용 도구가
   필요한 스킬은 도구 연결도 지원된 것으로 간주하지 않는다.
5. 압축은 정상 사용 중 발생한 이벤트로 확인한다. 비용을 들여 긴 대화를 인위적으로 만드는
   시험은 별도로 결정한다. 이후 다른 계정·GPT에서 이어받을 때 요약과 이후 대화가 전달되고,
   원본 기록이 보존되는지 확인한다. 이 단계에는 추가 요약 응답 사용량이 포함될 수 있다.
