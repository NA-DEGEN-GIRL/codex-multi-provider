# 업데이트 호환 안내와 메모 영역 표시 (수정 74)

> 아래는 수정 74 당시 동작입니다. 업데이트 가능 판정은
> [수정 78의 실제 서비스 비교](live-service-update-status-78.md)로 보완했습니다.
> 같은 IPC와 작업 유지 지원만으로 업데이트 가능하다고 판정하지 않습니다.

## 사용자 동작

제목줄에는 `Codex 작업 공간`만 표시한다. 수정 번호·빌드·복사는 왼쪽 아래에 유지한다. 그 아래의 호환성 안내는 실행 중인 서비스와 다음 실행 대상으로 선택된 배포 파일을 30초마다 비교하며, ↻ 버튼으로 즉시 다시 확인할 수 있다.

| 표시 | 의미 |
| --- | --- |
| 작업 유지하며 업데이트 가능 | 같은 IPC이고 실행 중인 서비스가 백그라운드 작업 유지를 지원한다. X로 관리창만 닫고 다시 실행할 수 있다. |
| 작업 종료 후 적용 필요 | IPC가 다르거나, 기존 서비스에 작업 유지 기능이 없다. 작업을 마친 뒤 완전 종료해야 한다. |
| 업데이트 호환성 확인 불가 | 서비스에 연결되지 않았거나 배포 정보가 없거나 손상되었다. 안전한 재실행으로 표시하지 않는다. |
| 관리창 최신 · 서비스 적용 대기 | 관리창은 최신이지만 실행 중인 서비스가 이전 번들이다. 작업은 계속되고 서비스 교체는 완전 종료 후 적용된다. |
| 관리창 최신 · 작업 유지 가능 | 현재 관리창과 서비스가 선택된 배포와 일치한다. |

확인은 파일 읽기와 기존 연결의 `supervisor.status`만 사용한다. 프로필 실행·중단·서비스 교체·다른 배포 실행은 하지 않는다. 응답 제한은 4초이며 실패하면 이전의 초록색 안내를 계속 남기지 않는다. 구버전에서 이 표시를 처음 사용하려면 새 관리창을 실행해야 한다.

## 배포 메타데이터

빌드한 Shell의 `--write-shell-compatibility` 경로에서 컴파일된 수정 번호와 IPC 상수를 `shell-compatibility.json`으로 기록한다. 이 경로는 UI나 서비스에 연결하지 않는다. 번들 고정 단계에서 이를 검증하여 `runtime-manifest.json`의 `shell_compatibility`에 넣는다. 메타데이터 누락·잘못된 형식은 배포 포인터 갱신 전에 실패한다. Shell만 바뀌어도 서비스 해시를 바꾸지는 않는다.

판정은 경로가 배포 디렉터리 내부인지, 실행 파일이 존재하는지, 스키마·수정 번호·IPC가 유효한지 검증한다. 이전 메타데이터와 알 수 없는 미래 스키마는 `확인 불가`다. 프로토콜 호환성은 기존 작업 유지 계약에 따른다. 향후 호환되지 않는 서비스 변경은 IPC 버전을 올려야 한다.

## 메모와 펼치기 메뉴에 따른 표시 영역 변경

기존 코드는 Windows 창 드래그의 `ENTER/EXITSIZEMOVE`에만 크기 적용 확인을 사용했다. 메모 폭·연결 상세·도구줄 재배치로 WPF 영역이 바뀌는 경로는 비동기 `SetWindowPos` 요청 직후 원본 창을 노출할 수 있었다. 아직 넓은 원본 창이 옆 메모 영역을 덮을 수 있는 경로다.

이미 표시 중인 뷰포트의 위치나 크기가 바뀌면 같은 제한된 복구 절차를 사용한다. 전환 중에는 관리창의 현재 표시 영역에 맞춘 DWM 화면을 표시하고 원본 입력 창은 관리창 뒤에 둔다. 실제 클라이언트 좌표·크기와 네이티브 영역이 목표에 맞는지 확인한 후 다시 노출한다. 포커스·부모·입력 큐를 바꾸지 않으며, 메모를 접고 다시 여는 동작이 필요하지 않도록 한다. 기존 시간 제한과 실패 시 원래 창으로 복귀하는 동작은 유지한다.

## 검증 범위

- 독립 테스트 프로세스에서 좁은 창, 메모 폭 변경, 펼치기 영역 높이 변경을 8차례 조합하여 네이티브 크기·원점·정확한 잘라내기 범위와 포커스 보존을 검사한다.
- 기존 드래그·프로필 전환·최소화 복원·복구 제한 검사를 함께 실행한다.
- WPF 최소 창 크기에서 호환성 안내의 각 상태와 새로 확인 버튼에 접근할 수 있는지, 제목줄은 간결하고 버전 복사 정보는 유지되는지 검사한다.
- 서비스·배포 경로·잘못된 메타데이터·호환 여부를 합성 자료로 검사한다. 번들 검사에서는 UI 버전만 달라졌을 때 서비스 해시가 같음을 확인한다.
- 실제 대화 중인 Codex 창을 자동으로 조작하거나 재시작하지 않는다. 실제 Electron 화면과 사용자 입력까지 이 테스트로 검증했다고 보지는 않는다.
