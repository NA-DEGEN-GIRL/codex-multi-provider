# SSH 버전 확인과 업데이트 예약 — 수정 77

SSH 호스트의 기본 Codex CLI, 기본 백그라운드 서비스, 작업 공간이 관리하는
프로필별 런타임은 별도 설치입니다. Windows 앱 업데이트만으로 모두 같은 버전이
되는 것으로 표시하지 않습니다.

## 사용 방법

설정 및 관리의 **SSH 업데이트 · 연결 준비**에서 프로필과 호스트를 확인합니다.
자동 확인은 기본으로 켜져 있고, 관리 런타임 자동 적용은 기본으로 꺼져 있습니다.

- 관리 런타임은 실행 중·준비된·제공되는 버전을 구분합니다. 제공 버전은 로컬에
  배포된 검증 가능한 Linux 묶음이며, 인터넷의 최신 공식 CLI라는 뜻이 아닙니다.
- 관리 업데이트 예약은 **선택한 프로필에 등록된 SSH 호스트 전체**에 적용됩니다.
  SSH 작업 종료가 확인될 때까지 기다리고, 로컬 작업은 유지합니다.
- 기본 Codex는 CLI와 실행 중 서비스 버전을 따로 표시합니다. 두 버전이 같다는
  표시도 공식 최신 버전 확인을 뜻하지 않습니다.
- 기본 Codex 업데이트는 작업 종료·서비스 재시작 확인란에 명시적으로 동의해야
  실행합니다. 공식 `codex app-server daemon update`는 기본 설치를 업데이트하고
  서비스를 재시작할 수 있으며, 관리 프로필의 자동 적용 대상으로 포함하지 않습니다.
- SSH 연결을 처음 설정하는 기존 준비 기능도 같은 화면에 있습니다.

직접 SSH에서 Codex를 쓰는 것도 가능합니다. 다만 기본 Codex와 작업 공간 프로필은
실행 환경이 다르므로 같은 작업을 동시에 실행하지 않고, 사용하는 쪽에서 업데이트를
관리하는 편이 상태를 파악하기 쉽습니다. 이 기능은 호스트의 모든 사용자를 잠그는
범용 작업 잠금이 아닙니다.

## 안전한 적용과 복구

`RemoteUpdates`는 설정·예약·대상을 관리 상태에 저장하고 최대 3개씩 비동기로 확인합니다.
화면 상태 조회는 SSH를 실행하지 않습니다. 프로필 세대, 설정 리비전, 호스트 식별,
대상 묶음을 고정하고 기존 `UpdateHooks`의 SSH 전용 유지보수 절차를 사용합니다.
새 SSH 연결을 제한한 뒤 각 관리 서비스의 유휴 상태를 확인하며, 실제 종료는
런타임의 원자적인 종료 절차와 writer/프로세스/잠금 해제 증명을 거칩니다.
로컬 Codex를 닫거나 다시 여는 프로필 재시작 경로를 사용하지 않습니다.

응답을 잃은 종료·시작 요청은 적용 기록으로 재확인합니다. 결과를 확인할 수 없으면
대기 또는 확인 필요 상태로 남기며 성공으로 표시하거나 같은 요청을 다시 실행하지
않습니다. 이전 묶음과 연결 기록은 보존하며 불명확한 실행을 무조건 되돌리지 않습니다.
유지보수 적용 이후의 취소는 안전한 복구가 확인되기 전에 연결 제한을 해제하지 않습니다.

기본 CLI는 관리 런타임의 원자적인 유휴 종료 API가 없으므로 자동 재시작하지 않습니다.
수동 적용은 호스트·실행 파일·버전 관찰값과 연결된 일회성 확인값을 사용합니다.
SSH가 끊겨도 원격의 비공개 적용 기록과 분리된 작업자가 결과를 추적합니다.
이미 진행 중이거나 결과가 불명확한 작업을 다시 실행하지 않습니다. 명령 성공은
검증 전에 저장하며, 일시적인 후속 조회 실패는 읽기 전용 재확인으로 완료할 수 있습니다.

기본 CLI에는 프로필의 `CODEX_HOME`이나 API 키 환경을 넘기지 않습니다. 인증 파일이나
대화 본문을 버전 검사에서 읽지 않으며, 외부 명령의 오류 본문을 UI에 그대로 출력하지
않습니다. 확인란은 작업 종료를 사용자가 확인하는 것이며, 이후 다른 터미널에서 새
작업을 시작하는 것까지 막지는 않습니다.

전체 회귀 검사에서 발견한 기존 테스트의 가정도 정리했습니다. 기본 엔진에서 외부

테스트에만 보고서 탐색·GUI 기동 대기 한도를 120초로 지정했습니다. 실행 중 출력
관찰, 전체 출력 표식, 자식 프로세스 완료 검증은 유지합니다.

새 빌드 게시만으로 실행 중인 작업을 재시작하지 않습니다. 새 서비스 적용 여부는
작업 공간의 업데이트 호환 안내를 따릅니다.
