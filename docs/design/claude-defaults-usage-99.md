# 수정 99 — Claude 기본값·UltraCode·사용량 및 명시적인 SSH 작업 소속

## Claude 설정

수정 98의 관리 앱은 컨텍스트 200,000 및 압축 85%를 항상 지정했다.
수정 99에서는 각각 `null`을 공식 Claude Code 기본값으로 취급한다.
컨텍스트와 자동 압축을 독립적으로 기본값/직접 설정 중 선택할 수 있다.
기존에 저장된 숫자는 임의로 초기화하지 않는다.

실행기는 기본 압축에 `--autocompact auto`를 사용한다. 프로필의 자동 컨텍스트는
모델 자체의 제한을 바꾸는 환경 변수로 전달하지 않는다. 현재 지원하는 Opus·Sonnet·Fable
별칭의 목록/공통 이력 전달 예산에는 1M을 사용하며, 알려지지 않은 모델 ID는
보수적인 200k 예산을 사용한다. 이 메타데이터가 계정의 모델 접근 권한을 늘리지는 않는다.
공통 이력 전달에는 시스템·도구 입력의 여유 공간을 남긴다.
직접 설정한 컨텍스트는 공통 이력 전달 예산이며, 기본 압축 모드에서는 Claude 자체의
모델 컨텍스트나 압축 시점을 제한하지 않는다. 작은 임계치가 필요하면 압축 비율도 직접 지정한다.

`ultracode`는 `max`의 별칭이 아니다. 공식 CLI에 그대로 전달하며, Codex 모델 목록에도
별도 effort로 등록한다. 기존 사용자의 effort 선택은 유지한다.
설치된 CLI 2.1.282의 간단한 `--help` 출력에는 빠져 있지만 공식 문서에는 지원 옵션으로 명시되어 있다.

## 구독 사용량

프로필 카드와 작업 바로가기에 Claude의 5시간·주간 남은 비율, 초기화 시간,
마지막 조회 및 오래된 값 여부를 표시한다. 모르는 값과 남은 0%를 구분한다.
토큰 사용량이나 추정 요금으로 구독 한도를 계산하지 않는다.

`claude_usage.py`는 공식 CLI가 반환한 `rate_limit_event`, 상태 줄의 한도 필드,
공식 `/usage` 화면의 전체 계정 한도를 정규화한다. 새로운 실제 턴에서 받은 값은 해당 프로필의 현재 계정 확인값이 같을 때만
저장한다. 다른 계정 로그인·로그아웃 시 예전 계정의 수치는 제거한다. 계정 확인값은
비밀 토큰이 아닌 인증 주체의 단방향 해시다. 자격증명 파일을 직접 열거나 OAuth 토큰을
별도 HTTP 요청에 복사하지 않는다.

자동 조회는 300초, 수동 조회는 최소 15초 간격이며 중복 실행을 합친다.
과거 창의 초기화 시간이 지나면 100%라고 추정하지 않고 오래된 값으로 표시한다.
확인 가능한 실제 한도 정보가 없는 경우에는 이유를 표시한다.

Windows에서는 `claude_usage_terminal.py`의 숨겨진 ConPTY로 고정된 `/usage` 명령만
실행한다. 모델 입력·도구·플러그인·후크는 사용하지 않으며, 18초 제한과 프로세스 트리 정리를
적용한다. 화면 원문은 메모리에서만 다루고 비율과 초기화 표시만 추출한다.
OAuth 로그인과 CLI 최초 설정은 별개다. 최초 설정 화면이 남아 있으면 자동으로 로그인이나
동의 절차를 진행하지 않고 `onboarding_required`를 표시한다. 설정 화면의
`Claude 첫 실행 설정` 버튼은 같은 프로필의 공식 CLI를 열며 사용자가 완료한 뒤 다시 조회한다.
실제 계정에서 최초 설정 대기와 숨김 터미널 정리는 확인했으나, 그 계정의 실제 비율은 아직 확인하지 못했다.

## SSH 작업 소속 지정

같은 Git common dir를 공유해도 원격 프로젝트를 제거하면 renderer가 그 worktree cwd의
Git 정보를 조회하지 않는 경우가 있다. 프로젝트 제거는 다른 프로젝트로 모든 작업을
명시적으로 이동하는 기능이 아니다. 삭제된 프로젝트 ID에 대한 명시 소속도 일부 목록의
필터에 남을 수 있다. 기존 [수정 96](ssh-worktree-project-grouping-96.md)의 등록 루트 보호와 별개다.

`remote_project_membership.py`는 사용자가 선택한 목적지로의 일회성 소속 지정을 지원한다.
실행 중 Electron의 `.codex-global-state.json`을 덮어쓰지 않고, 각 프로필 홈의
`.manager-remote-project-membership.json`에 요청과 대상 작업의 이전 소속만 저장한다.
다음 안전한 프로필 실행 준비(`app_preferences.prepare`)에서 목적지 등록 여부와 작업별
이전 상태를 대조한 뒤 원격 명시 소속을 설정하고 projectless 표시를 해제한다.
그 사이 사용자가 다른 곳으로 이동한 작업은 건너뛴다. 목적지가 제거됐으면 재생성하지 않는다.
다른 프로필에서 삭제한 목적지도 공통 프로젝트 기록으로 확인한다. 저장 도중 중단 후 재시도해도
이미 적용된 소속을 유지하며, 그 사이 명시적으로 프로젝트 밖으로 옮긴 작업은 다시 넣지 않는다.

실제 저장 완료 후 요청을 consumed 파일로 바꾸고, 대상 필드 백업과 결과를 같은 프로필 홈에 남긴다.
대화 내용·작업 cwd·워크트리·Git 브랜치·인증·실행 상태는 변경하지 않는다.
이 일회성 조치는 이후 새로운 작업까지 자동으로 같은 프로젝트에 배치하는 규칙이 아니다.
적용 여부는 `.manager-remote-project-membership-result.json`으로 확인한다.
지원 중인 26.917 렌더러와 메인 프로세스의 실제 분류 함수를 추출한 검사에서도
이 원격 배정 형식이 작업 폴더 추정보다 우선하며 로컬 기록 마이그레이션으로 제거되지 않음을 확인했다.

## 작업 바로가기 전환

기존 바로가기는 `conversation.open` 이후 전체 `state` 조회까지 기다린 뒤 화면을 붙였고,
요청 진행 표시줄이 펼쳐지면서 내부 창 높이도 줄었다가 다시 늘었다. 일반 프로필 선택은
이미 보관한 창을 즉시 사용하므로 체감 차이가 컸다.

이제 보관한 프로필 창은 즉시 표시하고, 응답의 창 실행 식별자를 확인해 연결한다.
전체 사이드바 갱신은 기존 주기 조회에 맡긴다. 아직 창이 준비되지 않았다면 기존
`conversation.navigate` 대기 흐름만 사용한다. 별도 전체 목록 조회를 추가하지 않는다.
작업 이동 진행 문구는 기존 상태줄에 표시해 내부 창의 크기가 변하지 않게 한다.
요청에 클릭 당시 프로필 ID를 포함하여 바로가기 연결이 중간에 바뀌면 다른 계정을 열지 않는다.

백엔드에서도 공통 기록 저장소 환경이 이미 결정된 경우 곧바로 버릴 프로필별 기록 목록을
만들지 않는다. 기존 개별 저장소를 쓰는 실행 경로의 목록 생성은 유지한다.
이 변경은 화면 연결과 불필요한 조회를 줄이며, 원격 서버나 Electron 자체의 작업 읽기 시간을
없앤다고 보장하지 않는다. 실제 클릭 후 체감은 새 관리창에서 확인해야 한다.

## 검증과 배포

### 설치된 데스크톱과 관리용 데스크톱

이 PC에 설치된 공식 26.924는 ASAR 무결성 검증이 켜져 있어 기존 관리용 패치 방식의
지원 대상이 아니다. 보호 설정을 변경하지 않는다. 원본 26.917 패키지도 더 이상 남아 있지 않았다.
`desktop_managed_upgrade.py`는 이전에 검증해 저장한 특정 26.917 관리용 패키지만 대상으로
추론 선택기 두 모듈을 새 디렉터리에서 갱신한다. 출발 패키지와 원래 어댑터의 해시를 고정해
검증하고, 추론 UI 이외의 어댑터가 달라지면 거부한다. 기존 패키지는 수정하지 않는다.
새 패키지 검증 후 기존 호환성 대체 실행 경로에서 사용할 수 있다. 이는 모든 최신 Codex
패키지를 지원하는 기능이 아니므로 후속 개발자는 검증 제한을 해제하지 말고 호환성을 별도로 조사해야 한다.
