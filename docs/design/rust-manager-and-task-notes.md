# Rust 관리 서비스와 작업 메모

2026-09-16 · 사용자 승인 범위: C# 창 유지, 관리·연결 Rust 전환, 작업별 자동 저장 메모/체크리스트. UI는 imagegen A안 선택.

## 문제와 경계

현재 UI 클라이언트, C# Supervisor, Python Backend가 각각 전체 요청을 직렬 대기한다. Python은 모든 요청 동안 전역 mutex를 잡고 있다. 느린 프로필 조회가 다른 프로필과 저장 요청까지 지연시킬 수 있다. Rust로 번역만 하는 대신 요청 ID로 응답을 분배하고, 작업 실행과 메모 저장을 분리한다.

- C# WPF: 창 호스팅/입력, 프로필 선택, 메모 편집기. Codex HWND 위에 겹치지 않는 별도 오른쪽 열.
- Rust 서비스: 사용자 전용 named pipe, 요청 분배/시간 제한, 프로필별 명령 순서, 프로세스 시작·식별·종료, 요청 진행 상태/오류 기록, 메모 저장.
- Python 호환 어댑터: 기존 계정·설정·카탈로그·SSH·업데이트 포맷과 정책을 재사용. 실행/종료 OS 작업은 Rust에 위임한다. Codex 엔진과 설치된 본앱은 교체하지 않는다.

Rust 서비스는 기존 프로토콜 주소를 유지하고 버전을 올린다. 구버전 서비스는 기존 retire 절차로 관리 요청이 없을 때 종료한다. 사용자 Codex 프로세스는 서비스 종료만으로 죽지 않는다. 응답 시간 초과는 요청 실패 확정과 구분하며, 이미 보낸 실행 명령을 자동 재전송하지 않는다. 프로필별 세대 번호와 PID 생성 시각으로 오래된 요청이 새 실행을 종료하지 못하게 한다.

## 작업 식별

메모는 `(host_id, thread_id)`에 연결하며 프로필/제목은 키에 포함하지 않는다. 따라서 같은 작업을 다른 계정으로 열어도 같은 메모다. 내부 Codex의 실제 route 변경 이벤트를 전달하며, 백그라운드에서 마지막으로 실행된 RPC를 선택 상태로 추정하지 않는다. 새 작업/설정 화면에는 작업 없는 상태를 표시한다. 로컬과 SSH 호스트를 분리한다.

## 메모 UX/저장

- A안의 얇은 탭, 넓은 편집 영역. 오른쪽 메모 버튼으로 열기/접기, 너비 조절.
- `+`에서 일반 메모 또는 체크리스트 생성. 탭 이름 변경, 삭제, 삭제 복구.
- 체크리스트: 항목 추가/수정/삭제, 완료 체크, 완료 수 표시.
- 변경 직후 저장 대기, 짧은 지연 후 자동 저장. 작업/탭 전환 시 기존 내용의 작업 키를 고정해 저장. 저장 중 새 입력은 보존.
- Rust가 작업별 파일을 원자적으로 교체하고 revision 충돌을 검출한다. 이전 revision을 조용히 덮어쓰지 않는다. UI는 저장 실패/충돌을 표시하고 편집 초안을 보존한다.
- 종료 직전 미저장 초안을 로컬 복구 파일로 남긴다. 실행 작업과 독립된 저장 경로이므로 Codex 요청 대기 때문에 메모 저장이 막히지 않는다.

## 확인할 동작

다른 프로필의 지연이 상태/메모를 막지 않는지, 종료된 연결의 늦은 응답, 잘못된 세대/PID 종료 거절, 서비스 재시작 후 상태, 동일 작업의 프로필 간 메모 공유, 다른 작업 격리, 빠른 작업/탭 전환, 한글 입력, 메모/체크리스트 저장·복구·충돌, 창 최소 크기/큰 DPI에서 메모와 내부 창이 겹치지 않는지 확인한다.

UI 후보는 `task-notes/concept-a.png`(선택), `concept-b.png`. 내장 imagegen을 사용했으며 프롬프트는 오른쪽 도킹, 작업 귀속, 가로 탭과 +, 저장 상태, 다크 테마 가독성, 기존 중앙 채팅 보존을 지정했다. 그림을 UI로 삽입하지 않고 WPF 실제 컨트롤로 구현한다.

참고: [Tokio Windows named pipe](https://docs.rs/tokio/latest/tokio/net/windows/named_pipe/struct.ServerOptions.html). 실제 사용자 앱의 강제 종료·포커스 전환 없이 격리 fixture로 검증한다.

## 구현·검증 결과 (2026-09-17)

- 배포 25 / IPC 27: `artifacts/manager/releases/20260916-152704-938`. 기존 실행 바로가기가 새 배포를 선택한다.
- C# Supervisor를 배포에서 제외하고 `codex-workspace-service.exe`를 넣었다. 계정·설정·카탈로그·SSH 호환 정책은 Python에 남겼고, 그 어댑터의 전역 요청 잠금은 프로필별 순서 제어로 바꿨다.
- Rust는 Tokio named pipe로 요청 ID별 응답을 전달한다. C# 클라이언트도 읽기·쓰기를 분리해 느린 요청과 메모 저장을 같은 연결에서 처리한다. 요청 취소가 이미 시작한 작업을 다시 실행시키지 않는다.
- 프로세스 종료는 세대 번호, PID 생성 시각, 전용 실행 파일 경로, 실제 `--user-data-dir`를 확인한다. OS 프로세스 핸들을 유지하며 자손만 종료하고 다른 프로필과 WSL 공유 프로세스를 보호한다. 종료 신호 중복 전송으로 생기던 Windows 오류를 격리 시험에서 발견해 수정했다.
- 메모/체크리스트는 오른쪽 실제 WPF 열이며 접기와 너비 조절을 지원한다. `+`로 종류 선택, `⋯`로 이름 변경/삭제, `+` 메뉴에서 최근 삭제 복구. 500ms 입력 지연 후 자동 저장한다.
- 저장 충돌은 다른 창의 내용을 유지하고 현재 편집을 `복구본` 탭으로 보존한다. 저장 실패/종료 때 초안 파일을 남긴다. 늦게 완료된 오래된 저장이 최신 초안을 덮어쓰거나 삭제하지 못한다.
- Rust 단위·프로세스·동시성 시험 9개, 실제 Windows IPC 통합 80개 검증, 별도 60초 유휴 종료 시험 통과. WPF 메모/체크리스트 11개 검증과 창 호스팅·제목줄·알림 자체 시험 통과. 기존 창 로직 시험 50개 통과.
