# 수정 104 — 계정 이메일 표시

작성: 2026-10-01. 이전 수정 98–103의 미커밋 작업을 유지한 추가 변경입니다.

## 사용 방법

프로필 제목 옆 **이메일 표시**를 누르면 각 Codex·Claude 프로필 이름 아래에
이메일이 한 줄로 나옵니다. 긴 주소는 말줄임하고 해당 줄의 툴팁에 전체 주소를
표시합니다. **이메일 숨기기**를 누르면 즉시 사라집니다. 외부 API·로컬 모델에는
이메일 줄을 만들지 않습니다. 정보를 확인할 수 없는 계정은 `이메일 확인 안 됨`으로
표시하고 다른 계정의 정보를 대신 사용하지 않습니다.

매번 앱을 열 때 기본값은 숨김입니다. 기존 Claude 카드의 부분 가림 주소도 기본
화면과 툴팁에서 제외합니다. 이 설정은 관리 앱의 계정 목록에 적용되며 사용자가
직접 입력한 별칭이나 내장 Codex 자체의 로그인 화면을 수정하지 않습니다.

## 데이터 경계

- `MainWindow.ProfileEmails.cs`: 창 메모리에만 표시 선택과 조회 결과를 보관합니다.
  숨기면 결과를 비우고 요청 세대를 바꿔 진행 중이던 조회가 나중에 도착해도 표시하지
  않습니다. 계정 연결이 달라져도 이전 결과를 사용하지 않습니다. 주기적인 상태
  갱신은 이메일을 다시 조회하지 않습니다. 동시에 최대 두 개만 조회합니다.
- `profile.email`은 명시적인 `reveal: true`가 필요한 관리 RPC입니다. 요청 인자는
  프로필 ID뿐이며 응답은 ID·결과 상태·이메일로 제한합니다. 기존 동일 사용자·권한
  관리 IPC 경계를 사용하고 새 네트워크 서버나 포트는 추가하지 않습니다.
- `profile_email.py`: Codex는 해당 프로필의 `auth.json`에서 표시용 이메일 메타데이터만
  읽습니다. 직접 로그인은 자체 HOME, 연결 계정은 지정된 source HOME을 사용합니다.
  저장된 계정 지문 및 토큰의 계정 ID가 다르면 표시하지 않습니다. 만료된 토큰의
  이메일도 재로그인할 계정을 식별할 수 있게 읽되, 이를 로그인 유효성 검증으로
  취급하지 않습니다. 인증 갱신·파일 쓰기·모델 호출을 하지 않습니다.
- Claude는 격리된 공식 CLI의 `auth status --json` 결과에서 이메일만 추가로 허용합니다.
  일반 `auth_status()`는 기존 부분 가림을 유지합니다. 공개 상태 저장 함수는 전체
  이메일을 받아도 저장하지 않습니다. CLI 원문·인증 토큰·오류 원문을 반환하지 않습니다.
- 이메일 조회는 프로필 수정 요청의 잠금을 점유하지 않습니다. 느린 Claude 상태 조회가
  해당 프로필 열기를 가로막지 않으며 조회 전후 연결이 달라지면 결과를 버립니다.

## 검증

- Python 이메일 검사 9개: 기본 조회 거절, 만료된 표시 정보, 잘못된 계정 연결,
  원본 HOME 선택, 잘못된/큰 파일, API·제거 계정 제외, Claude 출력 허용 목록,
  저장 시 제거, 동시 계정 변경, 관리 명령 연결을 검사했습니다.
- 관련 Claude 프로필 16개 및 CLI 어댑터 42개 기존 검사를 통과했습니다.
- WPF 실제 버튼 검사는 기본 숨김·조회 도중 숨김·지연 응답 무시·두 계정 유형 표시·
  한 줄 표시 및 툴팁·선택 유지·계정 변경·상태 갱신 시 재조회 없음·새 창 숨김·
  진단 로그에 이메일 없음에 대한 검사입니다. 합성 계정만 사용합니다.
- 현재 등록된 Codex 계정 7개의 로컬 표시 정보를 읽을 수 있음을 확인했습니다.
  실제 주소는 출력하거나 문서에 기록하지 않았습니다. 실제 Claude 로그인 조회는
  수행하지 않았고, Claude 경로는 합성 CLI 상태로 검증했습니다.

## 적용

새 관리 서비스의 `profile.email` 명령이 필요합니다. 구버전 서비스를 유지하면서 새
관리창만 열면 `관리 서비스 업데이트 필요`가 표시됩니다. 작업을 마친 후 기존
완전 종료·업데이트 절차로 관리 서비스까지 교체해야 합니다. 이 기능 때문에
진행 중 작업이나 프로필을 강제로 종료하지 않습니다.

이 변경은 관리 앱 후보로 빌드하며 현재 실행 파일·관리 서비스·원격 Codex는
자동 교체하지 않습니다. 수정 103의 런타임 활성화 상태는 그 수정 문서를 따릅니다.
