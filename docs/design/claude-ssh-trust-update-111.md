# 수정 111 — Claude SSH·프로젝트 신뢰와 공식 앱 업데이트

## 확인된 원인

1. Claude SSH 지원 소스와 Linux 후보는 준비돼 있었지만 기본 배포 디렉터리는
   이전 런타임이었다. `supports_remote_claude()`는 의도적으로 기본 배포만 검사하므로
   Claude 프로필의 SSH 설정 복사를 계속 제외했다.
2. 신뢰 승인은 프로필별 `config.toml`에만 있었다. 공통 기록에서 기존 작업을 열어도
   새 Claude 프로필에 승인 정보가 없으면 네이티브 실행기의 신뢰 검사가 거절했다.
3. SSH 프리셋 동기화가 데스크톱의 PATH에서 다시 SSH 중계기를 선택했다.
   내부 관리 명령이 네이티브 연결 명령 검사를 통과하지 못해
   `native_wrapper_changed`와 `ssh_preset_sync_required`가 연이어 발생했다.
4. 공식 MSIX 업데이트는 파일 준비와 등록이 별개다. 기존 코드는 등록 보류 상태에서
   원본 앱 실행만 안내하고 작업 공간에서 마지막 등록을 요청할 수 없었다.

## 변경

- Windows 런타임 후보 `20261001-072058-ac1f2c`를 기존 공유 편집·공통 저장소의
  동일 바이너리 검증 보고서로 활성화했다. Linux의 `claude105` 후보도 파일 해시와
  기능 표식을 검사하고 기본 배포로 선택했다. 이전 배포 파일은 보존했다.
- `project_trust.py`는 같은 OS 사용자의 공통 설정과 관리 프로필에 이미 명시된
  `trusted` 승인만 공유한다. 대상 프로필의 기존 결정과 `untrusted`를 덮어쓰지 않는다.
  Windows 경로를 Linux로 변환해서 신뢰하지 않는다. 인증·권한 정책을 복사하지 않는다.
- 로컬 프로필 준비와 작업 시작·재개·포크 요청 전에 승인 설정을 동기화한다.
  원격 준비는 해당 서버 사용자의 설정만 읽어 같은 규칙으로 합친다.
  Rust의 Claude 신뢰 검사는 그대로 유지한다.
- `ssh_shim._proxy_with_auth`가 이미 검증한 실제 OpenSSH 경로를
  `publish_before_connect`에 전달한다. PATH에서 중계기를 재선택하지 않는다.
- `registration_pending`에 **준비된 업데이트 적용** 버튼을 제공한다.
  이전 설치가 종료됐다고 확인된 경우에만 새 설치 요청 ID를 만든다. 캐시한 MSIX의
  해시·서명·패키지 신원을 다시 검사하며 강제 앱 종료 옵션을 사용하지 않는다.
- Windows가 파일 사용 중이라고 명시적으로 거절하면 등록 보류를 유지한다.
  완전 종료가 서비스 종료까지 확인한 뒤 `finish_package_update.py`를 실행한다.
  이 도우미는 부모 프로세스의 종료와 같은 업데이트 ID를 확인하고 한 번만 적용한다.
  단순 창 닫기는 업데이트를 시작하지 않는다. 불명확한 설치 결과는 자동 재시도하지 않는다.

## 검증과 제한

- 최종 동결 릴리스 `20261004-061537-236`에서 256개 검사를 실행했다.
  252개 통과, 4개 환경상 제외이며, 파일 해시 220개와 실제 로드된 동결 모듈 81개를 확인했다.
  같은 실행 파일의 창 제어·레이아웃·프로필 순서·개인 스킬·SSH 업데이트·Claude 설정
  화면 자체 검사 6종도 통과했다.
- 활성화한 Windows 네이티브 실행 파일로 오프라인 통합 검사 2개를 추가 실행했다.
  Claude 스트리밍·저장·재개와 GPT→Claude→GPT 문맥 인계가 통과했다.
  실제 모델 대신 가짜 CLI와 로컬 제공자를 사용했으므로 유료 모델 응답 검증은 아니다.
- 두 Claude 프로필의 세 서버 실행 정의를 준비했다. 서버별 설정에서 Claude 실행기와
  해당 서버에 이미 승인된 프로젝트 신뢰 정보가 반영됐음을 확인했다.
  실제 원격 연결 6개 모두 `connected`, `initialized`, `accountReady`가 참이고
  `thread/loaded/list` 요청이 성공했다. 이는 연결·인증 준비 검증이며 각 서버에서
  실제 모델로 기존 대화에 메시지를 보내는 검증까지 수행한 것은 아니다.
  원격 연결 검증 결과는 Git 밖 `claude-verification.json`에 보관한다.
- 실제 MSIX 등록 요청은 Windows의 파일 사용 중 응답으로 보류됐다. 이 결과를
  업데이트 완료로 표시하지 않는다. 실행 중 다른 프로필을 종료하지 않았다.
- 종료 후 도우미는 격리 시험으로 검사했다. 작업 중인 전체 앱을 종료해서 수행하는
  실제 패키지 등록 완료 검사는 이번에 수행하지 않았다.
- 관리 서비스는 실행 중 Python 사본을 계속 사용한다. 새 관리창만 열면 새 종료 후
  도우미를 사용할 수 있고, 모든 프로필을 완전 종료한 다음 시작하면 새 서비스 코드도 적용된다.
- 수정 111 관리창과 두 Claude 프로필의 새 SSH 중계기는 실행 중 환경에 적용했다.
  다른 계정의 작업은 재시작하지 않았다. 공식 패키지의 등록 보류는 새 관리창이나
  관리용 Codex 실행 파일의 적용 여부와 별개의 상태다.

개인 계정·호스트·프로세스 식별자가 포함된 상세 증거는 Git 밖
`work/validation/release-111/`에 둔다. 이 문서는 자격증명을 포함하지 않는다.
