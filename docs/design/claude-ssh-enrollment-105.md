# 수정 105 — Claude SSH 등록과 실행 준비

## 문제와 원인

수정 98–99의 Claude 실행기는 Windows 로컬용이었다. Linux에서 Windows 실행기와
인증 경로를 잘못 사용하지 않도록 SSH 연결 복사, 실행 환경 생성, 자동 준비를
제외했다. 수정 103에서 호스트별 Claude 실행기와 계정 연결을 구현했지만,
`ControlCenter`의 직접 준비·프로필 열기·기존 연결 확인에는 초기 제한이 남았다.

실행 중 서비스는 빌드별로 고정한 Python 사본을 사용한다. 소스를 고치거나 관리창만
다시 열어도 수정 99 서비스의 제한은 없어지지 않는다. 저장된 배포 포인터와 실제
실행 중 서비스 버전도 구분해야 한다.

## 변경

- `scripts/control_center.py::_open_profile_locally`: 검증된 SSH Claude 런타임을
  지원하면 원격 설정 적용 대기와 유지보수 상태를 일반 프로필과 같이 처리한다.
- `_prepare_remote`: 무조건 거절하던 조건을 지원 여부 검사로 바꾸고, 등록된
  Claude 계정·모델 설정을 전달한다. 실행 중 프로필은 현재 generation의
  `tracked-ssh-v1` 기록이 있어야 한다. 파일만 설치했다고 구버전 데스크톱에
  SSH 추적 기능이 생긴 것으로 취급하지 않는다.
- `_reconcile_remote_hosts`: Claude의 기존 연결도 확인한다. 시작 시 확인은
  새 실행기 설치나 프로세스 재시작을 수행하지 않는다.
- `manager/Shell/WorkspaceBuild.cs`: 수정 105 표시.

SSH 연결 복사, 원격 인증, Linux 실행기 및 프리셋은
[수정 103 설계](ssh-execution-presets-103.md)를 사용한다. 인증 토큰을 설정 파일이나
이 문서에 저장하지 않는다. 현재 실행 중인 다른 계정을 종료하지 않는다.

## 적용 상태와 다음 순서

**빌드와 서버 준비를 완료했으며, 실행 중 수정 99 서비스와 배포 포인터는 유지했다.**
관리 서비스 교체는 다른 프로필의 작업 종료 여부 확인 후 진행한다. 현재 Claude
프로필에 SSH 목록이 표시되거나 실제 답변이 생성됐다고 보고하지 않는다.

- 관리 앱 후보: `artifacts/manager/releases/20261001-162653-598/candidate.json`.
- 네이티브 Windows 후보와 같은 바이너리 검사 증거는 수정 103 문서의 경로를 따른다.
- Linux 후보: `artifacts/remote/candidates/claude105/linux-x86_64/manifest.json`.
  이 중첩 경로는 기본 배포와 지원 여부 검색에 포함되지 않는다. 현재 기본
  `artifacts/remote/linux-x86_64`는 그대로다.
- 비공개 준비 증거: `work/claude-ssh-preparation-105.json`. 호스트와 프로필
  식별자가 포함되므로 Git에 추가하지 않는다. 준비한 연결은 아직 활성 프로필
  목록에 등록하지 않았다.
- 빌드 증거: `work/manager-stage-105.log`,
  `work/manager-stage-105-remaining.log`, `work/stage-105-*.json`.

작업을 마친 뒤 기존 완전 종료 절차로 관리 서비스까지 종료하고, 검증된 관리 앱·
Windows 실행기·Linux 기본 묶음을 함께 적용한다. Windows 실행기는 기존
`scripts/activate_manager_runtime.py`의 동일 바이너리 증거 검증 절차를 사용한다.
임의로 실행 중 배포 파일을 덮어쓰거나 프로필 인증 종류를 위장하지 않는다.

새 서비스에서 Claude 프로필을 열면 공통 SSH 목록과 현재 generation의 추적기를
준비한다. 원격 연결을 등록하고, 해당 계정으로 연결된 프로젝트에서 작업 목록을
읽은 뒤 최소 답변을 확인한다. 마지막 답변 검사는 실제 구독 사용량을 소비한다.
이전 서비스와 기존 프로필은 성공이 확인될 때까지 복구 가능하게 보존한다.
