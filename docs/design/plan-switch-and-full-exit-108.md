# 수정 108 — 새 개인 플랜 화면 전환과 완전 종료

## 확인한 원인

2026-10-04 조사. 설치된 공식 패키지는 26.930.2377.0이지만 실행 중인 관리용
화면은 검증된 26.917.9434.0 사본이었다. 설치 버전과 실제 실행 버전은 다르다.
새 개인 플랜 식별자 `promax`는 구버전 화면의 플랜 enum, 허용 목록, 토큰
파서 및 개인 플랜 분류에 없었다. 개인 계정이 조직 설정 조회 경로로 들어가
`workspace-settings` 오류가 되고, 화면 전환 처리기는 이 오류에서 이동하지 않는다.
정상 로그인 상태라도 ChatGPT에서 Codex로 돌아갈 수 없는 경로다.

로컬 공식 26.930.2377.0 패키지의 `app-shared`에서 개인 플랜 목록이
`free, go, plus, prolite, pro, promax`인 것을 확인했다. 기존 관리용 사본에
이 분류와 토큰 해석을 반영했다. 계정 일치, 서버 인증, 조직 권한 확인을
제거하지 않았으며 알 수 없는 다른 플랜을 임의로 허용하지 않는다.
요금·결제 화면 전체나 네이티브 런타임의 모든 새 플랜 표기를 갱신한 것은 아니다.

완전 종료 기록에서는 로컬 Codex 10개가 종료된 뒤 SSH 종료 요청이
`profile_prepare_busy`로 거절됐다. `ProfileRestarts.schedule_remote()`가
명시적인 SSH 재시작만 종료 요청으로 전환하고, 일반 시작 과정의
`remote_background` 준비 작업은 전환하지 못한 것이 원인이다.

## 변경 위치와 보존하는 경계

- `scripts/manager_core/desktop_managed_upgrade.py`: 기존에 해시로 고정한
  관리용 사본에만 네 군데의 정확한 플랜 해석 지점을 변경한다. 원본이나
  실행 중인 사본은 수정하지 않고 별도 디렉터리에 게시한다. 공식 패키지의
  Electron 무결성 보호를 변경하지 않는다. 예상 지점이 없거나 중복되면 실패한다.
- `scripts/manager_core/profile_restart.py`: 일반 SSH 준비 중 들어온 명시적
  종료 요청도 같은 작업 ID로 전환한다. 일반 프로필 열기 자체가 원격 종료를
  허용하는 것은 아니다.
- `scripts/manager_core/update_hooks.py`: 종료 의도를 저장한 뒤 실행 경계에서
  기존 프로세스 식별 기록을 보존하며 drain으로 전환한다. 이미 시작을 확정한
  작업은 완료 뒤 새로 열린 실행을 종료한다. 재사용 완료와 종료 요청이 겹쳐도
  살아 있는 실행을 종료 완료로 발표하지 않는다.
- `manager/Shell/MainWindow.cs`: 이전 서비스가 한 프로필의 종료 요청을
  거부하더라도 나머지 프로필 요청을 계속한다. 확인하지 못한 원격 실행은
  기존의 명시적 선택 창에 함께 표시한다. 사용자가 선택하면 원격 실행을
  서버에 남겨 두고 로컬 앱을 종료할 수 있다. 강제 종료는 추가하지 않았다.

## 검증과 적용 범위

실제 수정 전·후 관리용 ASAR에서 플랜 판단 함수를 추출해 가상 계정으로
실행했다. 수정 전 새 플랜의 로컬 접근은 오류, 계정 접근은 거부였고 수정 후
둘 다 허용됐다. 계정 불일치·로그인 없음·알 수 없는 플랜·조직 설정 조회 오류를
계속 차단하는 것도 검사했다. 기록은 `work/validation/plan-switch-108/result.json`.

SSH 회귀는 일반 준비 대기 중 종료, 재사용 확인 중 종료, 시작 확정 후 종료,
완료 기록과 종료가 겹치는 경우를 포함한다. 프로세스 세대 변경, PID 재사용,
응답 유실과 다른 프로필 보존 검사도 유지한다.

최종 후보는 `artifacts/manager/releases/20261004-045528-854`.
WPF 레이아웃 검사는 `work/validation/plan-switch-108/layout.json`, 고정 후보
Python 검사와 전체 파일 해시 검사는 후보의 `fix-validation.json`에 기록한다.
고정 빌드에서 Python 179개와 파일 217개 해시 검사를 통과했다. 초기 고정 빌드
검사 한 건은 테스트가 임시 폴더를 변경하면서 실제 고정 모듈의 해시가 바뀌기를
기대해 실패했다. 호환성 fixture의 모듈 경로를 그 임시 폴더에 명시적으로 주입해
다시 전체를 통과했다. 실제 배포 파일이나 제품의 무결성 검사는 변경하지 않았다.
실제 계정 화면 전환, 실제 완전 종료, 공식 패키지 업데이트 설치는 이번
검사에서 실행하지 않았다. 새 공식 패키지에 대한 호환 검증을 대체하지 않는다.

다음 실행 포인터만 새 빌드로 게시한다. 실행 중인 서비스와 프로필은 유지한다.
기존 관리창을 X로 닫고 다시 열면 수정 108 관리창이 연결된다. 이전 서비스가
계속 실행 중이면 서버측 수정과 새 관리용 화면 적용은 아직 남아 있다.
작업을 마친 뒤 수정 108 관리창에서 완전 종료하고 다시 실행해야 전체가 적용된다.
이전 서비스의 SSH 종료 거절은 위 선택 창에서 처리할 수 있다. 원격 작업의
강제 종료를 요구하지 않는다. 롤백용 이전 포인터는 개인 작업 디렉터리
`work/validation/plan-switch-108/manager-current-before.json`에 보존한다.

공식 Codex 업데이트에는 별도로 새 버전 호환 확인이 필요하다. 관리용 사본을
고친 것만으로 공식 업데이트 설치 가능 또는 실사용 복구 완료라고 표시하지 않는다.
