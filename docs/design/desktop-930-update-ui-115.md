# 수정 115 — 프로필이 공식 Codex 26.930을 사용, 공식 앱 업데이트 적용, 관리창 UI 개편

## 1. 공식 앱 업데이트가 계속 "사용 중"으로 보류

### 원인
- 공식 Codex 패키지는 Windows 서비스 `CodexSandboxService.OpenAI.Codex`(자동 시작, LocalSystem, `desktop6:Service`)를 함께 설치한다.
- 이 서비스가 실행 중이면 Windows 배포 기록에 "활성 서비스 `OpenAI.Codex_2p2nqsd0c76g0!App`(으)로 인해 배포가 중단됩니다"(0x80073D02)가 남는다.
  새 버전은 "등록 지연"으로 표시되고, Windows의 자체 재시도(예: 07:01)와 «준비된 업데이트 적용» 모두 같은 이유로 실패한다.
- 관리용 사본은 패키지 밖에서 실행되므로, 작업 공간을 완전 종료해도 서비스는 남는다. 업데이트 전 검사는 다른 계정(SYSTEM) 프로세스의
  경로를 읽지 못해 서비스를 볼 수 없다.

### 변경
- `managed_package_update._quiet`: 공식 앱이나 관리용 사본의 Codex 창이 하나도 실행 중이 아니면, 패키지를 붙잡는 것은 그 서비스뿐이다.
  이때만 설치 요청에 `force_shutdown`을 넣는다.
  - 처음 설치(`apply`): 등록 지연 대신 바로 등록한다.
  - «준비된 업데이트 적용»·완전 종료 후 자동 적용(`finalize`): 서비스를 잠시 멈추고 등록을 마친다.
- `install_worker`: `force_shutdown`이면 `Add-AppxPackage -ForceApplicationShutdown`을 쓴다. 같은 PowerShell 안에서 직전에 `ChatGPT`
  프로세스를 다시 확인해, 그 사이 창이 열렸으면 실행하지 않고 "사용 중"으로 남긴다. 서비스는 자동 시작이라 등록 뒤 다시 실행된다.
- 창이 열려 있으면 이전처럼 아무것도 종료하지 않고 등록 지연으로 둔다.
- 실제 적용: 작업 공간의 Codex 창이 모두 닫힌 상태에서 서명·해시를 확인한 공식 패키지(26.930.3930.0)를 같은 방식으로 적용했고,
  서비스는 다시 실행 중이다.

## 2. 프로필이 업데이트된 공식 앱(26.930)을 사용

### 무결성 검사 유지(재봉인)
- 26.930부터 Electron 퓨즈의 ASAR 무결성 검사(`EnableEmbeddedAsarIntegrityValidation`)와 `OnlyLoadAppFromAsar`가 켜져 있다
  (`chrome.dll` 퓨즈 `010011001`). 이전 관리 코드는 이런 버전을 지원하지 않고 26.917 사본만 썼다.
- 검증 값은 `ChatGPT.exe` 리소스 안의 `{"file":"resources\\app.asar","alg":"SHA256","value":…}`이며, 아카이브 헤더 문자열의 SHA-256과 같다.
- `desktop_bundle.seal_archive_integrity`: 관리용 사본을 게시할 때 사본의 `ChatGPT.exe` 안 값만, 같은 길이로, 패치한 아카이브의 헤더 해시로 바꾼다.
  원래 값이 설치된 아카이브의 헤더 해시와 정확히 한 번 일치할 때만 바꾼다(아니면 지원하지 않는 버전으로 거절).
  - 퓨즈와 설치된 패키지는 바꾸지 않는다. 검사는 켜진 채로 사본의 아카이브를 검증하고, 바꾼 항목마다 블록 해시도 다시 계산한다.
  - 사본 `ChatGPT.exe`의 Authenticode 서명은 더 이상 맞지 않는다. 이 PC는 Smart App Control이 꺼져 있어 실행이 막히지 않는다.
  - 원본 계정 동기화 사본(`original_sync_bundle`)도 같은 방식으로 봉인한다. 화면 업그레이드 경로(`desktop_managed_upgrade`)는 26.917 전용이며
    무결성 검사가 켜진 기준 사본은 거절한다.
- 검증: 봉인한 실제 26.930 사본을 별도 사용자 폴더로 잠시 실행하면 패치한 코드가 그대로 실행된다. 같은 사본의 값 한 글자를 바꾸면 Electron이
  "Integrity check failed for asar archive"로 즉시 종료한다. 바뀐 바이트는 실행 파일의 해시 값 58자뿐이다.

### 26.930 패치 위치
- 바뀐 파일: 프로필 파이프는 `application-network-startup-*.js`(경로 바인딩 `c`), 주 프로세스 동기화는 `main-*.js`와 `bootstrap-*.js`로 나뉘었고,
  렌더러 동기화·보관 필터는 `webview/assets/app-shared-*.js`로 옮겨졌다.
- `desktop_bundle.patch_archive`: `app-shared`도 검사한다. 보관 필터·원격 프로젝트 묶음은 어느 청크에 있든 하나만 허용한다.
  추론 선택기 패치는 선택기 표식이 있는 파일(`app-initial`)에만 적용하고, 선택기 없이 추론 설정만 보이면 실패한다.
- `original_sync_bundle.main_sync_plan`: 동기화 지점이 한 모듈에 다 있으면 기존 방식, 아니면 26.930 표(`SPLIT_PATCHES`)의 각 지점이 전체
  주 프로세스 모듈 중 정확히 한 번 있어야 한다. 어댑터는 `getGlobalStateValue`가 있는 모듈 앞에 둔다.
- 새 변형: 알림 클릭(비동기 활성화 뒤 webContents 전달)·표시(포커스 창 억제 포함), 작업 맥락(주 `a.type`, 렌더러 React 컴파일러 형태),
  브라우저 도구 런타임(`:i}`), 렌더러 동기화(`RENDERER_PATCHES_930`), 보관 필터·원격 묶음 이름, 추론 검사기 `zve`, Chrome 호스트 이름.
- `desktop_record_sync.cjs`: 26.930의 `publishMutation`이 인자 하나만 받아도 빠른 경로를 인정한다.
- 개인 플랜(promax)은 26.930에 기본 포함되어 별도 패치가 없다. SSH 명령 형태는 바뀌지 않았다(26.917처럼 명령마다 검증).
- 검증: 실제 26.930.3930 아카이브에 저장소 코드를 적용하면 모든 지점이 정확히 한 번 바뀌고, 바뀐 6개 파일이 `node --check`를 통과한다.
  `test_desktop_isolation_headless.py`(번들 Node로 사본의 파이프 해석기를 실행)가 26.930에서 통과한다.

### 아직 실제 프로필로 확인할 것
- 26.930은 창을 띄우기 전에 `CODEX_CLI_PATH app-server`를 한 번 더 실행해 설정 요구사항을 읽는다(`startup-requirements`). 관리 프록시가
  같은 프로필의 상태 파일을 짧게 한 번 더 기록한다. 순서상 본 실행이 다시 기록하지만 실제 실행으로 확인해야 한다.
- 26.930은 `CODEX_ELECTRON_USER_DATA_PATH`를 늦은 변경으로 무시한다. 관리자는 `--user-data-dir=`도 넘기므로 프로필 분리는 유지된다
  (시험 실행에서 확인).

## 3. 완전 종료가 원격 Codex를 끝없이 기다림
- SSH 호스트 한 대의 프로필 04 원격 런타임(이전 묶음 98ad6b88)이 18시간 동안 tokio 작업 스레드 하나로 CPU 100%를 쓰며 신호를 처리하지 못했다.
  완전 종료는 이 런타임의 유휴 보고를 기다리다 멈췄다. 해당 프로세스만 종료했고(TERM 무응답, KILL), 다음 실행부터 새 묶음을 쓴다.
  원인 코드는 프로세스가 종료되어 확인하지 못했다.

## 4. 관리창 화면 개편(프로필 레일 + 작업 바로가기 전체 높이)
- 기존: 약 300px 한 열에 프로필 목록, 작업 바로가기, 전체 기록·설정·업데이트 안내·완전 종료가 쌓여 작업 바로가기가 한두 개만 보이고 카드 정보가 한 줄에서 잘렸다.
- 프로필 레일(기본, 64px): 프로필마다 번호(또는 2~3글자) 원형 아바타, 공급자 색(GPT·Claude·API·로컬), 주간 사용량 고리, 상태 점(준비됨 속 빈 점,
  주의 필요 시 주황). 선택한 프로필은 강조 고리와 왼쪽 막대. 마우스를 올리면 이름·상태·사용량 두 구간·초기화·리딤·하위 에이전트·SSH 호스트·안내를
  카드로 보여 준다. 아래쪽에 추가(+), 전체 기록, 설정 및 관리(주의 표시 배지), 펼치기, 완전 종료.
- 펼친 패널(304px): 이름 두 줄 줄바꿈, 오른쪽 위 상태, 주간·5시간 막대, 초기화·리딤, 칩. 펼침 상태는 `sidebar-layout.json`에 저장한다.
- 작업 바로가기 열(기본 280px, 240~440px 조절·저장): 개수, +, ⋯, 검색(제목·프로필 이름·SSH 호스트, Ctrl+F). 카드 제목 두 줄, 둘째 줄에 상태·프로필·SSH 호스트·하위 에이전트.
- 상단: 선택한 프로필 아바타·이름·상태·칩·사용량, 기존 도구 버튼, 최근 작업 줄. 업데이트 안내는 상단 배너와 설정 배지로 옮겼다.
- 좁은 창: 작업 영역이 760px 이상 남을 때만 작업 바로가기 열을 옆에 두고, 아니면 레일 버튼으로 겹쳐 연다.
- 동작 변화: 프로필은 마우스를 뗄 때 선택되고, 누른 채 끌면 순서를 바꾼다(손잡이 없음). 상태 줄은 아래 막대 한 줄(전체 내용은 도움말).
- 검증: 매니저 자체 시험 12개(배치 시험 재작성, 순서 시험에 클릭·끌기 구분 추가). 겹쳐 여는 패널과 설정 패널은 화면 밖 배치로만 확인했다.
