# 수정 108 — Codex 업데이트 사전 검사 오탐과 안내

## 확인한 원인 (2026-10-04)

실제 업데이트 요청은 설치 전에 `plan_not_ready`로 막혔다. 설치기는 시작하지
않았다. 당시 프로세스 조회에서 관리 중인 10개 프로필의 PID, 프로세스 시작
시각, 실행 파일이 저장된 식별 정보와 일치했다. 해당 메인 프로세스에서
파생된 Electron 프로세스도 모두 관리 대상으로 분류할 수 있었다.

`UpdateHooks.snapshot_instances()`는 먼저 `_live()`로 실행 파일과 프로세스
시작 시각을 확인한 뒤 로컬 및 SSH 작업의 유휴 상태를 조회한다. 뒤 단계가
예외를 던지면 원래 profile dict로 되돌아가서, 앞서 검증한 `executable`과
프로세스 시작 시각인 `created_at`을 잃었다. profile의 `created_at`은 프로필
생성 시각이므로 프로세스 시작 시각과 같지 않다. `UpdateManager._blockers()`는
이 응답을 미확인 프로세스로 판단하고 그 Electron 하위 프로세스도 미관리
실행으로 분류했다. 작업 상태 확인 실패가 '관리창 밖 Codex를 종료'라는 다른
원인의 경고까지 만들어 낸 것이다.

읽기 전용 관리 RPC 검사에서도 로컬 유휴 상태 조회 중 `runtime_error`가
관찰됐다. 원격 종료 증명, 이 RPC 오류 자체, 새 Codex 버전 호환성은 이번
진단 표시 수정으로 해결했다고 간주하지 않는다.

## 변경과 유지하는 조건

- 예외 이전에 검증한 프로세스 식별 정보는 유지한다. 다음 프로필에 이전
  프로필의 식별 정보를 재사용하지 않는다.
- 예외 이후에는 `idle_verified`와 `writer_release_verified`를 반드시 false로
  둔다. 로컬 확인 성공 뒤 SSH 확인 실패도 업데이트를 허용하지 않는다.
- 작업 진행 중, 로컬 상태 확인 실패, SSH 상태 확인 실패를 구분하고
  사용자 지정 프로필 이름을 함께 표시한다.
- 실제 미관리 프로세스, PID 재사용, 누락된 시작 시각은 계속 차단한다.
- 새 버전의 호환 검증이 없으면 창을 종료해도 설치할 수 없음을 명시한다.
  검증 기록을 임의 생성하거나 검사 조건을 우회하지 않는다.
- 관리창의 고정 높이 본문 대신 펼칠 수 있는 상세 안내와 스크롤을 사용한다.
  같은 원인이 여러 프로필에 발생해도 프로필별 항목을 보존한다.

수정 위치: `scripts/manager_core/update_hooks.py`, `updates.py`,
`manager/Shell/UpdatePresentation.cs`, `MainWindow.cs`.

## 검증과 적용

`test_manager_update_hooks` 42개 및 `test_manager_updates` 44개 통과.
실제 창이나 설치기를 조작하지 않는 fixture로 다음을 검사한다.

- 로컬 RPC 오류 및 SSH 조회 오류 뒤에도 관리 대상 프로세스와 그 하위
  프로세스가 미관리 실행으로 바뀌지 않는가.
- 위 두 오류가 여전히 유휴 확인 실패로 설치를 차단하는가.
- 다음 프로필의 식별 조회 실패 시 이전 프로필 정보를 재사용하지 않는가.
- PID 재사용과 실제 미관리 Codex 차단이 유지되는가.

관리창 레이아웃 검사에는 프로필 12개에 동일 오류가 난 fixture를 추가했다.
.NET 빌드는 경고·오류 없이 통과했고, WPF 레이아웃 검사도 통과했다.
검사 보고서는 `work/validation/update-preflight-108/layout.json`에 있다.

추가 수정 포함 후보는 `artifacts/manager/releases/20261004-044251-802/candidate.json`이다.
`-StageOnly`로 Rust 서비스와 .NET 구성요소를 빌드하고 Python 코드를 고정했다.
고정 후보에서 핵심 회귀 4개와 전체 bundle 파일 해시 검사를 통과했다.
후보 내 `update-preflight-validation.json`에 결과가 있다. 새 공식 Codex 호환
검증 결과가 아니며, 기존에 검증된 관리용 desktop 사본을 계속 사용한다.
기존 `20261004-042100-114` 후보에는 이 추가 수정이 들어 있지 않다.
`artifacts/manager/current.json`은 변경하지 않았다. 실행 중인 서비스와
프로필을 재시작하거나 실제 업데이트 설치를 수행하지 않았다.

이후 새 개인 플랜 화면 전환 및 일반 SSH 준비 중 완전 종료 수정을 합친
`20261004-045528-854`가 최종 빌드다. [최종 검증·게시·적용 순서](plan-switch-and-full-exit-108.md)를
따른다. 위 중간 후보의 미게시 상태와 최종 빌드의 다음 실행용 게시를 구분한다.
