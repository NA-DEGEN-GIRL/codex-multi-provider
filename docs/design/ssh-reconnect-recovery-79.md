# SSH 연결 유지와 업데이트 안내 — 수정 79

## 문제

앱을 다시 열 때 SSH 실행 파일과 도우미의 변경을 계정 설정 변경으로 취급하면,
연결을 재사용할 수 있는 계정도 재시작 절차에 들어갑니다. 이전 재시작이 일부 서버를
종료한 뒤 다른 서버의 종료를 확인하지 못하면 해당 계정의 SSH 연결은 보류됩니다.
자동 업데이트를 꺼 둔 경우에도 시작 시 준비 경로에서 이 문제가 발생할 수 있었습니다.

별개로, 연결 목록 복구가 서버의 준비 상태에 의존해 저장된 SSH 항목이 빠진 상태가
유지될 수 있었습니다. Windows에서 실제로 실행되는 SSH 스크립트는 Python 모듈을
다른 이름으로 중복 로드해, 알려진 연결 대기 오류마저 일반 시작 실패로 표시했습니다.

## 유지할 동작

- 설정이 같은 연결은 기존 SSH 실행 버전을 유지합니다. 새 파일이 있다는 것만으로
  실행 중인 서버를 교체하지 않습니다.
- 계정의 모델 설정 변경과 사용자가 요청한 SSH 업데이트는 구분합니다.
- 연결 선언과 자동 연결 선호는 서버의 실행 준비 상태와 구분합니다. 명시적으로 끈
  자동 연결 설정과 수동 서버 설정은 복구 과정에서 덮어쓰지 않습니다.
- 연결 확인 실패는 실행 버전 확인 실패나 실제 작업 진행 상태와 구분합니다.
- 종료 요청 이후 응답이 사라진 경우 같은 종료 요청을 반복하거나 실행 잠금을 지우지
  않습니다. 소켓 파일이 없다는 사실만으로 프로세스 종료를 판정하지 않습니다.
- 실제 스크립트 실행 경로에서도 알려진 오류 코드와 한국어 안내를 유지합니다.

연결 목록은 시작할 때만 고치지 않습니다. 앱이 일부 항목만 다시 저장한 경우에도
이전에 가져온 공통 항목 중 원본에 남아 있는 항목을 앱 자체 설정 저장소로 복원하고,
앱의 연결 목록 갱신 기능을 호출합니다. 명시적인 끄기 값은 유지하며, 실행 중인 설정
JSON을 직접 덮어쓰지 않습니다. 목록 갱신이 실패하면 설정을 반복 저장하지 않고
갱신만 간격을 두고 재시도합니다.

기존 연결은 서버의 해당 설정 파일 해시와 연결 식별 정보를 읽어 확인한 뒤에만
설정 지문을 보완합니다. API 키를 바꿀 때는 비밀값 대신 공급자 설정 세대를 올려
설정 변경을 감지합니다. 키나 키의 해시를 설정 지문에 넣지 않습니다.

안전한 종료 응답을 받은 시점의 기록과 실제 프로세스 종료는 별개로 보존합니다.
소켓 없이 남은 기존 프로세스, 미확인 종료 요청, 남아 있는 실행 잠금은 자동으로
삭제하거나 강제 종료하지 않습니다. 기존 작업을 보존해야 하는지 확인한 뒤 해당
계정의 실행만 대상으로 복구해야 합니다.

## 화면

‘작업공간에서 쓰는 Codex’와 ‘SSH 터미널에서 쓰는 Codex’를 별도 영역으로 표시합니다.
기본 화면에는 짧은 버전과 다음 동작을 안내하고, 긴 빌드 식별자와 오류 코드는
접을 수 있는 진단 정보에 둡니다. 상태가 확인되지 않으면 업데이트 완료나 안전한
재시작으로 표시하지 않습니다. 터미널 Codex 업데이트에는 기존 작업 종료 확인과
현재 상태 확인 절차를 유지합니다.

  JavaScript 회귀 검사 통과.
- 실제 서버에서는 연결 식별·설정 일치 여부와 오류 상태만 조회했습니다. 기존 사용자
  프로세스를 종료하거나 기본 Codex 서비스를 업데이트하지 않았습니다.
