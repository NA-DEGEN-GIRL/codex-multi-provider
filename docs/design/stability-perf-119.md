# 수정 119 — Claude·SSH 버그, 느린 관리창, 재발 방지 장치

## 1. 사용자가 만난 버그

### Claude 전환이 요약을 버림(런타임)
- 이전에 일부 턴을 본 Claude 세션을 이어 쓸 때, 그 세션이 본 첫 턴 뒤에 쓰인 요약(압축)을 모두 버렸다.
- 다른 공급자 작업이 길어 미확인 기록이 예산을 넘으면 `/compact`로 새 요약을 만들어도 전환이 거절됐다.
- 수정: 미확인 기록이 예산을 넘을 때에만 그 뒤의 요약도 쓴다(일부 내용이 겹치지만 거절보다 낫다).
- 참고: Claude 지원 전 GPT 서버 압축만 있는 작업은 GPT 계정에서 `/compact`를 한 번 해야 Claude가 읽을 수 있는 요약이 생긴다.
- 런타임 패치 `ccc7fae5`. Linux 번들 `0.153.4-managed-ccc7fae566c2323d`는 SIGHUP 종료 감사를 통과했다. Windows 교차 빌드본은 공유 편집·공통 저장소·Claude e2e와 실제 기록 DB 시작을 통과했다.

### SSH Claude 러너가 결과 없이 종료
- 원격 실행에는 관리 저장소가 없는데, 사용량 이벤트(한도에 가까워질 때 수치가 담겨 옴)를 저장하려다 `AttributeError`로 러너가 끝났다.
- 화면에는 "runner exited without a terminal response", 진행 중이던 도구 호출은 "Interrupted"로 보였다. 러너 오류 출력이 버려져 원인이 남지 않았다.
- 수정: 원격 실행은 사용량 이벤트를 저장하지 않고, 사용량 캐시의 형식 오류가 턴을 멈추지 않게 했다. 세 서버의 Claude 프로필 러너 사본에는 같은 한 줄을 즉시 적용했다.

### SSH 포크 대화의 메모가 빈 메모로 나옴
- SSH 포크 관계는 기록된 적이 없었고(로컬 DB만 읽음), 메모 서비스는 로컬이 아닌 호스트의 포크 부모를 무시했다.
- 수정: 원격 카탈로그 도우미가 롤아웃 첫 `session_meta` 줄에서 `forked_from_id`만 읽어 보고(대화 내용 없음), 관리자가 호스트별 포크 관계를 합치고, 메모 서비스가 SSH 포크도 부모의 메모 그룹을 공유한다. 기존 메모 파일은 덮어쓰지 않는다.

### SSH worktree 대화가 프로젝트 목록에서 사라짐(데스크톱 26.930.4958)
- 화면은 worktree 폴더의 git 정보를 그 폴더의 대화가 창에 열려 있을 때만 조회했다. 요약만 있는 원격 행은 조회하지 않고, 어느 프로젝트에도 맞지 않으면 버렸다.
- 프로필마다 결과가 달랐던 것은 원격 런타임 버전이 아니라, 그 창에 해당 폴더의 대화가 열린 적이 있었는지의 차이였다.
- 수정 96의 SSH 루트 보호는 4958의 함수 이름이 달라 조용히 빠져 있었다.
- 수정(`original_sync_bundle.py`, `desktop_bundle.py`):
  - 원격 요약 행도 git 정보를 조회한다.
  - 4958·3930용 수정 96 보호를 넣었다.
  - 등록되지 않은 worktree 대화는 사이드바 순서와 관계없이 저장소 프로젝트로 간다. 등록된 worktree 루트의 대화는 제자리에 둔다.
  - 26.930.x에서 이 패치들이 빠지면 조용히 넘어가지 않고 게시를 거부한다.
  - 4958에서 빠져 있던 호스트별 보관 필터도 넣었다.

## 2. 느린 관리창(측정 기반)
- **플러그인 재복사:** 데스크톱이 설치 표시 파일을 같은 내용으로 다시 쓰면 수정 시각만 보고 공유 플러그인을 12개 홈에 다시 복사했다(약 175MB, 시작 대기 최대 38초). 이제 표시 내용으로 판단하고, 시작 중에는 감시 스레드를 기다리지 않으며, `config.toml` 해석을 캐시한다.
- **대화 열기 지연:** 실행 중인 프로필의 Browser 구성 복구가 대화 열기 요청 안에서 384개 파일을 다시 복사했다(12~22초). 이제 백그라운드에서 바뀐 파일만 복구하고, 시작 직전에는 진행 중인 복구를 기다린다.
- **상태 조회:** 매 조회(분당 14회, p50 0.9초)마다 state.json을 다시 해석하고 포크 관계를 다시 읽었다. 이제 바뀌지 않은 상태는 재사용하고, 포크 갱신은 30초 간격이며, 작업 폴더 계산도 캐시한다.
- 한 번의 시작 파동 안에서는 데스크톱 사본 검사 결과를 재사용한다(30초, 첫 실행만).
- 관리창: 같은 대화 열기를 다시 눌러도 오류 없이 합치고, 진행 표시 애니메이션 빈도를 낮췄다.

## 3. 재발 방지 장치
- **활성화 관문:** 릴리스 빌드가 아닌 후보, 마이그레이션 목록이 없는 후보, PE 검사 기록이 없는 교차 빌드를 거부한다. 디스크에 없는 런타임을 `previous.json`에 쓰지 않는다.
- **되돌리기:** `scripts/rollback_manager_runtime.py --mark-good / --rollback / --mark-bad`. 정상 확인한 런타임만 되돌릴 대상이 되고, 알려진 불량 런타임은 활성화하지 않는다.
- **원인 기록:** 런타임이 끝나면 종료 코드·가동 시간·initialize 완료 여부를 `runtime-state.json`의 `last_exit`에 남긴다.
- **상태 점검:** `python scripts/health_report.py`가 런타임 포인터, 활성화 안 된 후보, 기록 DB와의 마이그레이션 호환(DB가 런타임보다 앞선 마이그레이션 포함), SSH 업데이트 대기, Claude 토큰 남은 시간, 관리창 릴리스를 읽기 전용으로 보여 준다.
- **SSH 업데이트 알림:** 관리창이 적용 가능한 SSH 런타임 업데이트를 알린다(이미 예약된 호스트는 세지 않음).
- **빌드 서버:** 압축 해제된 `codex`가 지나치게 크면 묶음을 거부한다.

## 남은 과제
- 새 런타임·관리창 적용 시 프로필을 한 개씩 재시작하고 실패하면 자동 되돌리기(단계적 적용).
- 화면이 준비되기 전 대화 이동 요청을 보내지 않게 하기(05 무한 로딩의 근본 수정).
- '다시 열기'의 종료 대기(12초)가 짧아 실패로 보고되는 문제.
- SSH 원격 런타임 33곳을 최신 묶음으로 맞추기: 예전 묶음은 sqlx 루프로 종료되지 않을 수 있어, 완전 종료 때 멈춘 프로세스를 확인하며 진행한다. 끝난 뒤 자동 적용을 켠다.
- upstream(0.160 이후)과의 차이: 공식 앱이 기록 DB를 런타임보다 앞서 마이그레이션한다. 상태 점검으로 감지하고, 장기적으로는 런타임을 새 upstream으로 옮긴다.
