# 화면 합성 배율과 DeepSeek 연결 검사 (수정 75)

## 드래그·메모 화면

수정 74의 네이티브 창 위치 확인 이후에도 화면 합성 캐시에 별도 문제가 있었다. DWM 업데이트를 생략하는 조건이 표시 영역과 표시 여부만 비교했다. WPF가 먼저 작은 영역을 배치하고 원본 창이 비동기로 나중에 작아지면, 원본 크기 변경 후에도 목적지가 같다는 이유로 갱신을 건너뛸 수 있었다. 드래그 때 합성 화면만 보여 주면 이전 배율이 드러나는 경로다.

- 원본 창의 클라이언트 영역을 창 좌표의 명시적 `rcSource`로 전달한다. 암묵적인 클라이언트 영역 선택 대신 원본과 목적지를 함께 지정한다.
- 갱신 생략 조건에 원본 클라이언트 범위와 `DwmQueryThumbnailSourceSize` 값을 포함한다. 원본 창이 늦게 바뀌어도 다시 적용한다.
- 드래그·영역 복구를 시작할 때 한 번은 합성 매핑을 다시 적용한다. 매 프레임 창을 재연결하거나 화면을 새로고침하지 않는다.
- 숨긴 프로필은 원본 크기를 계속 조회하지 않는다. 표시할 때 다시 맞춘다. 키보드 포커스·부모·입력 큐와 기존 복구 제한은 유지한다.

Windows API 근거: [DWM 원본·목적지 영역](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ns-dwmapi-dwm_thumbnail_properties), [원본 크기 조회](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/nf-dwmapi-dwmquerythumbnailsourcesize).

검사에서는 별도 네이티브 창의 목적지를 고정한 채 원본만 네 번 크게/작게 바꾸고, 실제 DWM 갱신과 클라이언트 영역 잘라내기를 확인한다. 기존 작은 창·메모·펼치기·드래그·포커스 보존 검사도 함께 실행한다. 이는 실제 Electron 화면을 픽셀 단위로 비교한 검사는 아니며, 사용 중인 대화 창은 자동 조작하지 않는다.

## DeepSeek 연결 검사

기존 연결 검사는 첫 요청에 `tool_choice={type:function,name:manager_probe}`를 강제했다. 구성된 DeepSeek 추론 모드에서 이 요청이 HTTP 400으로 거절되는 것을 실제 API로 재현했다. API 키 실패나 실제 대화의 연결 실패를 의미하는 결과가 아니었다. DeepSeek의 [도구 선택 제한](https://api-docs.deepseek.com/api/create-chat-completion/)에도 추론 모드의 강제 도구 선택 제한이 명시되어 있다.

DeepSeek의 추론 강도가 `none`이 아니면 첫 요청에 `auto`를 사용한다. 설정한 추론 강도를 낮추거나 끄지는 않는다. 텍스트가 돌아왔다는 이유만으로 성공 처리하지 않고, 여전히 정확히 한 번의 `manager_probe` 호출·임의 검증 값·도구 결과를 사용한 두 번째 응답을 모두 검사한다. 첫 응답의 추론 항목도 후속 요청에 그대로 보존한다. 다른 공급자와 DeepSeek `none` 모드의 기존 강제 선택 방식은 유지한다.

실제 설정의 `max` 강도로 스트리밍·도구 호출·도구 결과 후속 응답을 통과했다. 합성 문자열만 전송했고 사용자 작업 내용과 키는 출력하지 않았다. 실제 검증 중 공급자 설정·검증 버전은 바꾸지 않았다. 합성 단위 검사에는 DeepSeek 강도별 도구 선택, 추론 항목 전달, 도구를 호출하지 않은 응답의 실패 처리를 추가했다.

## 적용 경계

화면 수정은 새 관리창으로 재실행하면 적용된다. 연결 검사 코드는 관리 서비스의 Python 번들에 들어간다. 작업 유지를 위해 이전 서비스에 연결한 상태에서는 `서비스 적용 대기`가 표시되며, 연결 검사 수정은 작업을 마친 뒤 완전 종료·재실행해야 적용된다. 실행 중인 작업에 새 서비스 코드를 강제로 주입하지 않는다.
