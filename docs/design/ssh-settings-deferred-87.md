# SSH 설정 변경 후 무한 대기 복구 (수정 87)

## 확인한 원인

2026-09-23, 하위 에이전트를 설정하고 프로필을 다시 열면 로컬 창은 열리지만
SSH 세 서버가 준비 대기에서 멈췄다. 별도 OpenSSH 접속은 모두 성공했다.
기존 shared-record 런타임은 exclusive managed-source 모드가 아니어서
`app.managed.requests.pending_completion` 진단값과 `thread/managedIdleStatus`
증명을 제공하지 않았다. `maintenance.inspect()`가 누락된 진단값을 `idle=False`로
반환하여, 열린 대화가 없는 첫 서버에서도 전체 연결 준비가 끝없이 기다렸다.

## 변경

- `scripts/remote_helpers/maintenance.py`: 필수 진단값 누락은
  `remote_idle_diagnostics_unavailable`로 구분한다. 실제 요청·작업이 남은 경우와
  증명 자체를 지원하지 않는 경우를 같은 busy 값으로 처리하지 않는다.
- `scripts/manager_core/ssh_deferred_settings.py`: 설정 적용이 아직 시작되지 않은
  SSH 전용 준비 기록에 한해, 각 서버의 기존 프로세스·리비전을 읽기 전용으로 확인한다.
  모두 일치하면 이전 binding으로 연결을 복구하고 입장 차단을 해제한다.
- `pending_policy_hosts`와 별도 `deferred_policy_hosts`를 유지한다. 새 원격 설정 적용,
  새 정책 리비전 승격, 원격 파일 업로드, 서버 시작·종료는 하지 않는다.
  관리창에는 **SSH는 기존 설정으로 연결됨 / 새 하위 에이전트·모델 설정은 적용 보류**라고 표시한다.
- 세대·정책·binding·준비 기록·다른 유지보수 작업을 네트워크 확인 후 다시 검증한다.
  이미 stop/start를 요청했거나 일부 서버가 종료된 준비 기록은 이 경로로 되돌리지 않는다.
- 설정 보류 안내가 있어도 연결이 복구된 프로필은 클릭할 때마다 다시 준비하지 않는다.
- 새 설정이 실제로 시작·검증되어 게시되면 해당 서버의 두 보류 목록을 함께 제거한다.

## 이미 실행 중인 구버전의 복구

다음 도구는 기존 서비스가 고정된 옛 Python 코드를 사용하여 패치를 즉시 읽을 수 없는
경우를 위한 수동 복구 도구다. 실제 개인 ID를 소스에 넣지 않는다.

```powershell
python -X utf8 scripts/recover_ssh_settings.py --root . --profile <profile-uuid> --resume-previous-settings
```

대기 중인 SSH 전용 준비 기록과 지원되지 않는 상태 조회를 먼저 확인한다.
새 트랜잭션/작업 ID로 옛 워커의 권한을 무효화한 뒤 위 복구 경로를 사용한다.
옛 워커의 늦은 응답은 새 연결을 다시 차단할 수 없다. 기존 작업 기록은 journal에 보존한다.
이 명령은 새 하위 에이전트 설정을 강제로 적용하는 명령이 아니다.

## 검증과 한계

- 빌드 `20260922-154739-955`를 다음 실행 배포본으로 준비했다. Shell 수정 87, IPC 27.
- 관련 Python 검사 388개 중 387개 통과, 플랫폼 조건으로 1개 제외. Windows 빌드 성공.
- Python 회귀 검사: 필수 진단값 누락, 정상 busy, 기존 binding 복원, 정책 미승격,
  세대/정책/manifest/journal 변경 경쟁, 일부 종료 기록 거부, 다른 원격 리비전 거부,
  구버전 워커의 늦은 응답을 검사한다.
- 실제 해당 프로필의 세 서버에서 읽기 전용 identity 확인 후 로컬 연결 설정을 복구했다.
  기존 앱이 자동 재연결한 뒤 세 서버 모두 `auth-state: ready` 로그를 확인했다.
  실제 원격 작업 종료·모델 요청·유료 API 호출은 수행하지 않았다.
- 이 수정은 구형 shared-record 런타임에 없는 안전한 재시작 증명을 새로 제공하지 않는다.
  그 런타임이 계속 실행되는 동안 새 원격 모델/하위 에이전트 설정은 보류된다.
  열린 대화가 없다는 사실만으로 프로세스를 강제 종료하지 않는다.
- 새 관리창은 기존 서비스를 재사용할 수 있다. Python 백엔드 수정은 서비스 교체가 필요하므로
  X로 닫았다 여는 것만으로 모든 백엔드 코드가 교체됐다고 판단하지 않는다.
  실제 실행 중인 서비스와 선택된 배포본을 구분해서 확인한다.
