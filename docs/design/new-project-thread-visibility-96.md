# 수정 96 — 새 프로젝트를 만든 창에서만 폴더의 기존 대화가 보이지 않는 문제

## 증상

한 프로필에서 로컬 프로젝트를 새로 만들었다. 그 폴더(예: `D:\dev\new-app`)에는 전에 CLI 등으로
만든 대화가 이미 있었다.

- 다른 프로필 창은 새 프로젝트 아래에 그 대화를 바로 보여 준다.
- 프로젝트를 만든 창에는 하나도 보이지 않는다. 대화는 `채팅` 목록에 남는다.
- 기존 프로젝트에 폴더를 추가하거나 폴더를 바꿀 때도 같다.
- 프로젝트 선언(`local-projects`)과 카탈로그 DB는 모든 프로필에서 같다. 프로젝트를 만든 창의
  전역 상태만 다르다.

## 원인

Codex 26.917 main process의 `t8e`(26.915는 `B6e`)에서 생긴다. 이 함수는 로컬 프로젝트의 폴더가
바뀌기 직전에 실행된다(`assignUnassignedThreadsBeforeProjectRootsChange`). 프로젝트 만들기, 폴더 추가,
폴더 편집, 작업공간 루트 추가가 모두 이 경로를 쓴다.

1. 바뀌는 폴더의 대화를 `thread/list`(cwd 필터)로 읽는다.
2. 할당도 projectless 표시도 없는 대화 중에서, 기존 프로젝트가 가진 폴더에 있지 않은 대화를
   projectless로 표시한다. 새 프로젝트를 빈 상태로 시작하게 하려는 원래 앱의 동작이다.
   기존 프로젝트 폴더에 있는 대화는 그 프로젝트에 할당한다.
3. projectless 표시는 그 창의 전역 상태(`projectless-thread-ids`)에만 저장된다. 이전 할당과 새 할당이
   모두 없으므로 `thread/metadata/update`를 보내지 않는다. 공통 저장소의 `project_id`는 NULL 그대로다.
4. 렌더러의 프로젝트 화면 범위(`JUr`)는 projectless 대화를 `excludeThreadIds`에 넣는다.
   사이드바 분류(`DXr`)도 이 대화를 건너뛴다. 그래서 만든 창에서는 프로젝트가 비어 보인다.
5. 다른 프로필은 공유된 프로젝트 선언만 받는다(`desktop_local_workspace_sync.cjs`). 그 창은 `t8e`를
   실행하지 않으므로 폴더 기준으로 대화를 새 프로젝트에 넣는다.

## 수정

- `scripts/manager_core/desktop_project_membership.cjs`
  - `globalThis.__codexProjectMembership.projectlessPins`를 추가했다. 항상 빈 목록을 돌려준다.
  - 이 객체는 기록 신호 폴더가 설정된 관리 프로필에만 있다. 이 프로필들은 프로젝트 선언을 공유한다.
- `scripts/manager_core/original_sync_bundle.py`
  - `main_projectless_pin_patches()`를 추가했다. `t8e`의 마지막 `assignIfUnassigned` 호출에서
    projectless 목록 `D`만 `(globalThis.__codexProjectMembership?.projectlessPins?.(D)??D)`로 바꾼다.
  - 26.917(`n.$u`)과 26.915(`n.Iu`)의 이름을 모두 받는다.
  - 식이 없으면 패치하지 않는다(원래 동작). 두 번 이상 있으면 `ValueError`로 멈춘다.
    이미 패치된 번들에는 다시 적용하지 않는다.
  - `patches_for()`가 동기화 진입점 패치와 함께 돌려준다. 그래서 관리용 복사본(`desktop_bundle.py`)과
    원본 동기화 복사본이 모두 이 패치를 넣는다. `desktop_bundle.py`는 바꾸지 않았다.
  - 설치된 26.917에서는 `main-*.js` 한 파일에 동기화 패치 7개와 이 패치 1개가 적용된다.
    적용한 결과는 `node --check`를 통과한다.
- 바뀌지 않는 것
  - 기존 프로젝트 폴더에 있는 미할당 대화를 그 프로젝트에 할당하는 동작. 공통 저장소에 그대로 쓴다.
  - 사용자가 직접 `채팅`으로 옮긴 대화. 이미 projectless이므로 계속 `채팅`에 있다.
  - 자동화 실행, projectless 새 대화 등 다른 경로의 projectless 표시.
  - 어댑터가 없는 실행(관리하지 않는 원본 앱). 패치된 식이 원래 목록을 그대로 쓴다.
- 결과: 프로젝트를 만든 창도 다른 프로필처럼 폴더의 기존 대화를 새 프로젝트 아래에 보여 준다.
  관리 프로필에서는 "새 프로젝트는 빈 상태로 시작"하는 원래 동작이 없어진다. 모든 창이 같은 목록을
  보이도록 이쪽을 택했다.

## 한계

- 수정 전에 기록된 projectless 표시는 지우지 않는다. 사용자가 직접 `채팅`으로 옮긴 표시와 구분할 수
  없기 때문이다. 그런 대화는 그 창에서 프로젝트로 끌어다 놓으면 된다. 이 이동은 공통 저장소에 기록된다.
- Codex가 새 버전으로 바뀌어 식 모양이 달라지면 패치는 조용히 빠진다(원래 동작).
  번들 확인 검사가 관리용 26.915/26.917 복사본을 보므로, 새 버전에서는 식을 다시 확인해야 한다.

## 반영

패치 파일과 어댑터가 바뀌면 관리용 데스크톱 복사본의 키도 바뀐다. 관리자를 다시 빌드한 뒤
각 프로필을 새로 실행하면 적용된다. 이미 실행 중인 창은 다시 시작할 때까지 원래 동작이다.

## 검사

`tests/test_desktop_project_create_membership.py`(11개)

- 패치 선택: 식이 한 번 있으면 패치 하나를 만들고 projectless 목록만 바뀐다. 26.915 이름도 받는다.
  없거나 모양이 바뀌면 패치하지 않는다. 두 번 있으면 거부한다. 이미 패치된 번들은 그대로 둔다.
- Node 동작 검사: 26.917 번들에서 그대로 가져온 `t8e`, `n8e`, `JUr`로 만든 창과 다른 프로필의
  프로젝트 화면을 계산한다.
  - 패치 전: 프로젝트를 만들면 폴더의 대화 5개가 projectless로 표시된다. 만든 창에는 0개,
    다른 프로필에는 5개가 보인다(증상 재현). 기존 프로젝트에 폴더를 추가해도 같다.
  - 패치 후: projectless 표시를 쓰지 않고 두 창의 목록이 같다. 기존 프로젝트 폴더의 미할당
    대화는 그대로 그 프로젝트에 할당된다.
  - 어댑터가 없으면 패치 전후 결과가 같다.
- 두 복사본(관리용, 원본 동기화) 모두 패치와 어댑터를 같은 모듈에 넣는다.
- 번들 확인: 이 컴퓨터에 관리용 26.915/26.917 복사본이 있으면 대상 식이 정확히 한 번, 동기화 패치와
  어댑터가 들어간 모듈에 있는지 확인한다. 26.917은 함수 전체가 번들과 같은지도 본다.

`tests/desktop_project_membership_test.cjs`에서 `projectlessPins`가 빈 목록을 돌려주는지 확인한다.

변이 검사: 어댑터를 이전 상태로 되돌리거나 목록을 그대로 돌려주게 하면 동작 검사와 복사본 검사가
실패한다. `patches_for()`에서 이 패치를 빼면 진입점 검사와 복사본 검사가 실패한다. 두 번 이상 있는 식을
거부하지 않게 하면 거부 검사가 실패한다.
