# 관리창 업데이트 중 작업 유지 (수정 73)

## 동작

- 제목줄 X와 Alt+F4는 WPF 관리창 프로세스를 종료한다. 원본 Codex 프로필 프로세스, Rust 서비스, Python 관리 어댑터와 그 어댑터가 유지하는 SSH 연결은 남는다.
- 관리창 안에 표시하던 Codex 창의 연결을 해제하고 숨긴다. Electron의 기존 `released` lease를 사용하며, 창 부모나 입력 큐를 변경하지 않는다. 사용자가 별도 창으로 분리한 창은 그대로 둔다.
- 마지막으로 선택한 프로필만 `work/control-center/workspace-session.json`에 원자적으로 저장한다. 대화·전송 요청·입력 초안을 복제하거나 재전송하지 않는다. 다시 열면 실행 중인 동일한 창에 연결한다. 시작 중 직접 선택하거나 알림을 열었다면 사용자의 새 선택을 우선한다.
- 왼쪽 아래 **완전 종료…**는 확인 후 백그라운드 실행 준비를 멈추고, 관리 중인 프로필들을 정상 종료한 뒤 남은 소유 프로세스를 정리한다. 별도로 실행한 본앱은 종료 대상에 포함하지 않는다.

## 업데이트 경계

관리창 빌드와 작업을 담당하는 서비스의 수명을 분리한다. 다른 번들 해시라도 IPC 버전이 같고 프로필이 실행 중이면 새 관리창이 기존 서비스에 접속한다. 이때 서비스 코드·SSH 어댑터 교체는 미루고 로그에 알린다. 모든 프로필이 종료되고 관리 작업도 없을 때만 기존 서비스를 교체한다.

서비스는 연결된 관리창이 없어도 실행 중이거나 상태가 불확실한 프로필이 있으면 자동 종료하지 않는다. 60초의 연결 유예시간은 프로필 종료가 확인되고 관리 작업도 없을 때만 적용된다. 명시적인 서비스 교체도 같은 조건을 검사한다.

구버전 서비스에는 이 유지 정책이 없으므로 최초 적용 시 작업을 정리하고 완전 종료해야 한다. IPC가 다른 업데이트는 실행 중인 작업을 강제로 끊지 않고 호환 불가를 알린다. 업데이트된 서비스 기능까지 사용하려면 완전 종료 후 다시 연다.

## 범위

작업 유지 중 CPU·메모리 사용과 모델 요청은 계속될 수 있다. 승인이 필요한 작업은 일반적인 승인 대기 상태로 남는다. Windows 재부팅, 로그아웃, 프로세스 강제 종료나 장애를 넘어 RAM의 실행 상태를 복구하지는 않는다. 이미 종료된 프로필은 다시 시작할 수 있지만 중단된 요청을 자동 재전송하지 않는다.

## 검증

실제 사용자의 창이나 계정 대신 별도 루트·테스트 프로세스로 검사한다.

- 서비스 단위 검사: 실행 중, 알 수 없는 상태, 잔존 PID, 진행 중인 관리 작업이 있을 때 종료 거부.
- C# 실제 named-pipe 통합 검사: 관리창 연결 없이 76초 동안 테스트 작업이 계속 출력하고, 번들 버전 변경 후에도 동일한 서비스·어댑터·작업 PID에 다시 연결함을 확인.
- 기존 프로필을 명시적으로 종료하면 서비스와 어댑터가 정리되고 새 서비스가 접속 지점을 이어받는지 확인.
- WPF/Win32 검사: 일반 닫기와 완전 종료 버튼을 구분하고, 숨긴 독립 창을 종료하지 않은 채 동일한 HWND에 다시 연결하는지 확인.
- UI 선택 저장이 없거나 손상되었거나 미래 버전이어도 작업 요청을 재생하지 않고 초기 상태로 열기.

이 검사는 실제 장시간 Codex 추론이나 SSH 작업의 종료·재연결을 직접 수행한 결과와 구분한다. 실행 중인 사용자 작업은 테스트를 위해 종료하지 않는다.

2026-09-20 검증 결과: Rust 24개 검사와 Clippy, 실제 클라이언트 프로세스 종료를 포함한 C# 통합 검사 97개 단언을 통과했다. 서비스 자동 종료 유예시간을 넘기는 76초 작업 유지 검사와 작업 종료 후 서비스 자동 정리 검사도 포함한다. 배포 빌드의 Win32 호스트, 제목줄, 응답성, 알림, 메모, 레이아웃, 프로필 정렬, 공통 스킬 자체 검사를 모두 통과했다. Electron 창 표시 회귀 검사도 통과했다. 공개 후보 480개 파일의 Gitleaks 검사에서 탐지는 없었다.
