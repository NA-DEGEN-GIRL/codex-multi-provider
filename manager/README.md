# Codex 작업 공간 관리 앱

계정별 Codex 창을 하나의 작업 공간에서 열고, 작업·프로젝트·개인 스킬을 공유하는 Windows 앱입니다. 로그인·사용량·외부 모델 선택은 프로필별로 관리합니다.

## 사용

1. 저장소 루트의 `Open-Control-Center.cmd` 또는 시험판 `Open-Feedback-Test.cmd`를 실행합니다.
2. `프로필 ＋`에서 Codex 로그인이나 외부 API 프로필을 추가합니다.
3. 프로필을 선택해 작업을 엽니다. 드래그 또는 우클릭 이동 메뉴로 프로필 순서를 바꿉니다.
4. 프로필 우클릭의 `하위 에이전트 설정`에서 외부 모델의 사용 범위를 지정합니다. 외부 API 프로필의 `외부 모델 기본 설정`은 주 대화의 모델 기본값·컨텍스트·자동 압축 기준을 설정합니다. 대화에서 명시한 추론 강도는 기본값보다 우선합니다.
5. `설정 및 관리`에서 공통 개인 스킬·SSH·공급자를 관리합니다. 작업 메모에서는 본문과 체크 항목을 함께 작성합니다.
6. 제목줄 `X`는 관리창만 종료합니다. 실행 중인 Codex 작업과 SSH 연결은 백그라운드에 남으며, 다시 실행하면 같은 프로세스에 연결합니다. 모두 중단하려면 왼쪽 아래 `완전 종료…`를 누릅니다.

수정 73부터 호환되는 관리창 업데이트는 작업을 유지한 채 적용할 수 있습니다. 새 창은 기존 관리 서비스를 재사용하며, 서비스 자체의 업데이트는 완전 종료 후 적용합니다. 이 기능을 처음 도입하는 구버전 서비스나 IPC가 달라지는 업데이트는 작업을 마친 뒤 한 번 완전 종료해야 합니다. Windows 재부팅·로그아웃·강제 종료 뒤에 진행 중인 실행까지 이어지는 기능은 아닙니다. [동작과 검증 범위](../docs/design/workspace-lifetime-73.md)를 참고하세요.

작업 바로가기는 모든 계정에서 보입니다. 바로가기의 열 계정을 바꾸거나 링크를 삭제하는 것은 대화 본문 삭제와 다릅니다. 본앱도 공통 기록을 사용하려면 `Open-Synced-Codex.cmd`로 실행합니다.

로그인 정보, 공급자 API 키, 실제 기록과 설정은 로컬 `work/` 아래에 저장하며 Git에서 제외합니다. 최초 저장소 통합은 기존 작업이 종료된 뒤 실행합니다. 작업 중 프로세스를 강제로 종료하면 저장되지 않은 입력이 사라질 수 있습니다.

수정 74부터 왼쪽 아래 버전 표시 밑에서 **작업 유지하며 업데이트 가능 / 작업 종료 후 적용 필요 / 업데이트 호환성 확인 불가**를 확인할 수 있습니다. 30초마다 자동 확인하며 ↻ 버튼으로 즉시 갱신합니다. 제목줄에는 앱 이름만 표시합니다. [호환성 판정과 메모 영역 표시 개선](../docs/design/workspace-update-viewport-74.md)을 참고하세요.

## 구조와 빌드

Windows x64, .NET 10 SDK, Python 3이 필요합니다. Rust 관리 서비스, WPF Shell, Supervisor, RuntimeProxy와 Python 관리 모듈로 구성됩니다. Rust 런타임 소스 복원은 [패치 안내](../patches/README.md)를 따릅니다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-manager.ps1 -SelfTest
```

빌드는 `artifacts/manager/releases/<빌드 시각>`에 저장하고 `artifacts/manager/current.json`이 다음 실행 파일을 지정합니다. 실행 중인 앱을 자동으로 재시작하지 않습니다. 키를 명령행 인수나 진행 로그에 넣지 않으며, 관리 통신은 현재 Windows 사용자로 제한한 named pipe를 사용합니다.

자체 시험은 별도 시험 창을 사용합니다. 실제 Codex의 한글 입력·팝업·SSH·DPI·장시간 사용까지 자동으로 검증했다는 뜻은 아닙니다. 구체적인 결과와 남은 범위는 [설계 기록](../docs/design/)을 확인하세요. 과거 시험의 상세 로그·프로필 식별자·개인 서버 이름은 배포 소스에서 제외합니다.
