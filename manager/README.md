# Codex 작업 공간 관리 앱

계정별 Codex 창을 하나의 작업 공간에서 열고, 작업·프로젝트·개인 스킬을 공유하는 Windows 앱입니다. 로그인·사용량·외부 모델 선택은 프로필별로 관리합니다.

## 사용

1. 저장소 루트의 `Open-Control-Center.cmd` 또는 시험판 `Open-Feedback-Test.cmd`를 실행합니다.
2. `프로필 ＋`에서 Codex 로그인이나 외부 API 프로필을 추가합니다.
3. 프로필을 선택해 작업을 엽니다. 드래그 또는 우클릭 이동 메뉴로 프로필 순서를 바꿉니다.
4. 프로필 우클릭의 `하위 에이전트 설정`에서 외부 모델의 사용 범위를 지정합니다. 외부 API 프로필의 `외부 모델 기본 설정`은 주 대화의 모델 기본값·컨텍스트·자동 압축 기준을 설정합니다. 대화에서 명시한 추론 강도는 기본값보다 우선합니다.
5. `설정 및 관리`에서 공통 개인 스킬·SSH·공급자를 관리합니다. 작업 메모에서는 본문과 체크 항목을 함께 작성합니다.
6. 제목줄 `X`는 관리창만 종료합니다. 실행 중인 Codex 작업과 SSH 연결은 백그라운드에 남으며, 다시 실행하면 같은 프로세스에 연결합니다. 모두 중단하려면 왼쪽 아래 `완전 종료…`를 누릅니다.

수정 73부터 호환되는 관리창 업데이트는 작업을 유지한 채 적용할 수 있습니다. 새 창은 기존 관리 서비스를 재사용하며, 서비스 자체의 업데이트는 완전 종료 후 적용합니다. 이 기능을 처음 도입하는 구버전 서비스나 IPC가 달라지는 업데이트는 작업을 마친 뒤 한 번 완전 종료해야 합니다. Windows 재부팅·로그아웃·강제 종료 뒤에 진행 중인 실행까지 이어지는 기능은 아닙니다. [동작과 검증 범위](../docs/design/workspace-lifetime-73.md)를 참고하세요.

작업 바로가기는 모든 계정에서 보입니다. 바로가기의 열 계정을 바꾸거나 링크를 삭제하는 것은 대화 본문 삭제와 다릅니다. 본앱도 공통 기록을 사용하려면 `Open-Synced-Codex.cmd`로 실행합니다.

로그인 정보, 공급자 API 키, 실제 기록과 설정은 로컬 `work/` 아래에 저장하며 Git에서 제외합니다. 최초 저장소 통합은 기존 작업이 종료된 뒤 실행합니다. 작업 중 프로세스를 강제로 종료하면 저장되지 않은 입력이 사라질 수 있습니다.

수정 74부터 왼쪽 아래 버전 표시 밑에서 **작업 유지하며 업데이트 가능 / 작업 종료 후 적용 필요 / 업데이트 호환성 확인 불가**를 확인할 수 있습니다. 30초마다 자동 확인하며 ↻ 버튼으로 즉시 갱신합니다. 제목줄에는 앱 이름만 표시합니다. [호환성 판정과 메모 영역 표시 개선](../docs/design/workspace-update-viewport-74.md)을 참고하세요.

## Windows 실행 권한

수정 85부터 `설정 및 관리 → Windows 실행 권한…`에서 다음 실행에 관리자 권한을 요청하도록 설정할 수 있습니다. 한 번만 요청하려면 `Open-Control-Center-Admin.cmd`를 사용합니다. Windows의 UAC 허용 창에서 같은 계정으로 승인해야 합니다. 왼쪽 아래에는 관리창과 관리 서비스의 실제 권한을 각각 표시합니다.

권한 변경은 **작업을 마친 뒤 완전 종료하고 다시 실행할 때** 적용됩니다. 수정 86부터 `설정 및 관리 → 완전 종료 후 관리자 실행…`에서 종료 확인 후 UAC를 요청하고 다시 열 수 있습니다. 일반 서비스가 남아 있을 때 관리자 실행기를 열면 기존 작업에 일반 권한으로 연결하고 전환 대기를 표시합니다. 설정 저장이나 제목줄 X만으로 기존 서비스의 권한은 바뀌지 않습니다. 일반 모드로 돌아올 때는 체크를 해제하고 완전 종료한 뒤 일반 권한의 탐색기에서 실행하세요. [관리자 전환 수정·실제 UAC 검증](../docs/design/administrator-transition-86.md).

Codex의 `전체 액세스`와 Windows 관리자 권한은 별개입니다. 이 설정은 SSH 서버의 sudo 권한을 부여하지 않습니다. [구현·검증 범위](../docs/design/windows-execution-mode-85.md), [인수인계](../docs/HANDOFF.md), [복원 검사](../docs/RESTORE-CHECKLIST.md)를 참고하세요.

수정 89부터 관리 프로필의 로컬 작업에서 확인된 기본 ‘전체 액세스’ 선택을 저장합니다. 다시 열기 요청에 권한이 빠진 경우에만 마지막 선택을 보완하며, 새로 선택한 제한 권한을 덮어쓰지 않습니다. 적용 전 기록은 추측해 복원하지 않으므로 새 버전의 프로필에서 원하는 권한을 한 번 선택하세요. [권한 유지 범위와 검증](../docs/design/permission-selection-persistence-89.md).

## 내장 브라우저

수정 88부터 프로필을 열거나 다시 연결할 때 실행할 앱과 같은 버전의 내장 브라우저
구성요소를 확인하고 누락·손상 파일을 복구합니다. 기존 버전과 로그인 정보는 유지하며,
`Open-Synced-Codex.cmd`에도 같은 실행 전 검사를 적용합니다.
[원인·실행 중 복구·검증 범위](../docs/design/browser-bundle-recovery-88.md).

## SSH 업데이트

새 서버의 CLI·관리 런타임 설치 위치, Ubuntu 샌드박스 준비, 세션 복원과 프로필별 적용은
[새 SSH 호스트 준비 안내](../docs/operations/ssh-host-onboarding.md)를 참고하세요.

서버 강제 재부팅 후 대화 재개 오류나 웹 포트 전달 문제가 생기면
[SSH 기록 복구·웹 연결 확인](../docs/operations/ssh-crash-history-recovery.md)을 참고하세요.
대상 작업만 백업하여 복구하는 수동 도구이며 다른 작업을 일괄 초기화하지 않습니다.

수정 89부터 프로필 우클릭의 **SSH 작업 종료 후 설정 적용**으로 해당 프로필의
진행 중인 원격 답변이 끝나기를 기다린 뒤 모델·하위 에이전트 설정을 반영할 수 있습니다.
새 서비스의 **완전 종료**는 등록된 프로필의 원격 종료도 확인합니다.
이전 서비스에 연결한 경우에는 첫 종료가 로컬에만 적용됨을 따로 안내합니다.
[프로필별 종료 범위와 검증](../docs/design/profile-remote-drain-89.md).


수정 87부터 기존 SSH 실행이 안전한 재시작 상태 확인을 지원하지 않으면 무한 대기 대신
확인된 기존 연결을 복구하고 **새 SSH 설정 적용 보류**를 표시합니다. 이 상태의 원격 작업은
이전 하위 에이전트·모델 설정을 사용합니다. [원인·복구 조건·검증 범위](../docs/design/ssh-settings-deferred-87.md).

SSH 연결·업데이트 화면에서 관리 런타임과 기본 Codex CLI·서비스 버전을 확인할 수
있습니다. 자동 확인은 켜져 있고 관리 런타임 자동 적용은 기본으로 꺼져 있습니다.
관리 업데이트는 SSH 작업 종료까지 예약할 수 있으며 로컬 작업은 유지합니다.
기본 Codex 업데이트는 작업 종료·재시작에 명시적으로 동의해야 실행합니다.
[적용 범위와 복구 동작](../docs/design/ssh-updates-77.md)을 참고하세요.

## 구조와 빌드

수정 95는 관리 앱을 시작할 때 마지막으로 선택했던 프로필(알림을 눌러 시작하면 그 알림의
프로필)을 먼저 엽니다. 나머지 프로필은 그 프로필의 실행이 끝나거나 실패할 때까지 기다린 뒤
수정 94처럼 함께 시작합니다. 기다리는 시간은 그 프로필이 시작한 때부터 길어도 30초, 앱 시작부터
길어도 45초입니다. 기다리는 동안 다른 프로필을 누르면 그 프로필도 바로 시작하고, 나머지는
마지막으로 누른 프로필을 기다립니다. 이미 시작한 실행은 멈추지 않습니다. 첫 창은 약 22-26초,
마지막 창은 약 90-100초로 예상합니다(수정 94: 66초, 74초). 여러 프로필이 함께 시작되는 동안
관리창이 25초 만에 "창을 찾지 못했습니다" 오류를 내던 문제도 고쳐, 서비스가 실행 중으로 보고하는
동안에는 최대 90초(알림으로 연 경우도 같음)까지 여는 중으로 표시하며 기다립니다. 함께 배포하는
런타임은 수정 94의 압축용 평문 요약 요청이 캐시를 타지 못해 사용량을 늘리던 문제를 고칩니다(실측
97% 캐시). 완전 종료 후 다시 실행해야 적용됩니다.
[선택한 프로필 먼저 시작](../docs/design/parallel-profile-launch-94.md#수정-95-선택한-프로필-먼저-시작).

수정 94는 서로 다른 프로필을 한 번에 하나씩이 아니라 함께 준비해 시작합니다(동시 실행 수는
CPU에 맞춰 최대 8). 같은 프로필·업데이트·유지보수와 한 번뿐인 기록 이전은 여전히 단독으로
돕니다. 시작 직후 실패한 프로필 창이 기록 없이 남아 완전 종료 뒤에도 살아 있던 문제를 고치고,
완전 종료가 모든 프로필의 남은 창을 확인합니다. 새 런타임은 GPT 자동 압축 뒤 다른 공급자로
같은 작업을 이어 갈 때 평문 요약으로 문맥을 넘깁니다. 완전 종료 후 다시 실행해야 적용됩니다.
[병렬 시작](../docs/design/parallel-profile-launch-94.md) ·
[완전 종료 누락](../docs/design/full-exit-unsaved-launch-94.md) ·
[공급자 간 문맥](../docs/design/cross-provider-context-94.md).

수정 93은 계정 간 작업 기록 동기화를 관리 서비스의 허브로 모읍니다. 각 계정이 다른 계정의
신호 파일을 훑고 같은 작업을 여러 번 다시 읽던 것을 변경마다 한 번으로 줄이고, 다시 열 때
밀린 기록을 재생하지 않습니다. 허브를 쓸 수 없으면 기존 파일 방식으로 동작합니다. 시작 때
개인 스킬 동기화가 상태 잠금을 오래 쥐어 프로필 시작이 늦던 문제도 고칩니다. 완전 종료 후
다시 실행해야 적용됩니다. [설계·검증](../docs/design/record-hub-93.md).

수정 92는 상태 갱신 지연, 프로필 표시 후 창 연결 대기, 첫 알림 때의 관리창 멈춤을 줄이고
SSH 프로젝트의 내장 브라우저에서 원격 `127.0.0.1:<포트>` 주소가 빈 탭으로만 열리던 문제를
고칩니다. 쌓인 SSH 작업 기록과 로그인 검사 폴더는 새 서비스가 백그라운드에서 정리합니다.
관리 서비스와 프로필 실행에 적용되므로 새 빌드 후 **완전 종료하고 다시 실행**해야 합니다.
[원인·변경·적용 후 확인](../docs/design/responsiveness-and-ssh-browser-92.md).

수정 91은 `지금 열린 작업 추가`의 창 포커스 검사와 만료된 프로필의 재로그인 흐름을
보완합니다. `로그인 · API 키 관리`에서 기존 실행이 남아 있으면 해당 프로필의 종료를
확인한 뒤 전용 로그인 화면을 엽니다. [동작·검증 범위](../docs/design/shortcut-login-recovery-91.md).

수정 90은 전체 액세스를 선택한 프로필의 Windows 샌드박스 설치 실패와,
내부 Codex 클릭 시 관리 창이 뒤에 남는 창 순서 처리를 보완합니다.
[원인·권한 보존·검증 범위](../docs/design/sandbox-setup-window-activation-90.md).

Windows x64, .NET 10 SDK, Python 3이 필요합니다. Rust 관리 서비스, WPF Shell, Supervisor, RuntimeProxy와 Python 관리 모듈로 구성됩니다. Rust 런타임 소스 복원은 [패치 안내](../patches/README.md)를 따릅니다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-manager.ps1 -SelfTest
```

빌드는 `artifacts/manager/releases/<빌드 시각>`에 저장하고 `artifacts/manager/current.json`이 다음 실행 파일을 지정합니다. 실행 중인 앱을 자동으로 재시작하지 않습니다. 키를 명령행 인수나 진행 로그에 넣지 않으며, 관리 통신은 현재 Windows 사용자로 제한한 named pipe를 사용합니다.

자체 시험은 별도 시험 창을 사용합니다. 실제 Codex의 한글 입력·팝업·SSH·DPI·장시간 사용까지 자동으로 검증했다는 뜻은 아닙니다. 구체적인 결과와 남은 범위는 [설계 기록](../docs/design/)을 확인하세요. 과거 시험의 상세 로그·프로필 식별자·개인 서버 이름은 배포 소스에서 제외합니다.
